# M5.2 — Allow writes to the userdata partition only
Status: done (2026-11-10) · Milestone: M5 · Needs phone: yes · Depends: M5.1

## Why
Ubuntu Touch needs a writable `/userdata` (it holds `ubuntu.img`), and Halium's own `/init` runs `e2fsck -y` and may run `resize2fs` on it (M3.7 caveat, `tasks/M3.7-halium-initramfs-data.md`). Every 6.18 kernel so far blocks all UFS writes (`A50_UFS_SAFE`).

## Facts / unknowns
- userdata is `sda32` (PARTNAME=userdata), ext4, `data=journal` on the baseline (`log/2026-11-10-M3.7-halium-initramfs.md`).
- The guard is default-deny in the UFS core (`drivers/ufs/core/ufshcd.c`, M3.5). It must stay deny for every other LBA range: EFS, SEC_EFS, CPEFS, PARAM, bootloader and vendor stay untouched (CLAUDE.md rule 5).

## Owner decisions (2026-11-10)
- Backup: `ubuntu.img` only, taken before any write.
- First boot that can write: approved, once the backup is verified.

## Steps
1. Extend the guard to an allow-list of one LBA range: userdata, from the GPT read on the phone. Unit-test it on the host like M3.5's self-test, and keep a boot-time self-test.
2. First write test on a scratch file inside `/userdata`, then `e2fsck -n` (read-only check) before and after.
3. Only then let Halium's `/init` run its own checks (M5.3).

## Acceptance criteria
- [x] Writes outside userdata are still refused (self-test log): boot self-test passed on an invalid, a synthetic and the real range; host test 0 wrong decisions, 14/14 mutants caught; every other partition also read-only in software; 0 blocked commands during the test.
- [x] A scratch file written on 6.18 reads back on the baseline; `e2fsck -n` clean before and after (write test 2).
- [x] `log/2026-11-10-M5.2-userdata-writes.md`.

## Result
Backup: `ubuntu.img` 6442450944 B, sha256 22cb95a5… (laptop = phone), at `../a50-ubuntu-img-backup/`. Kernel `a50-userdata` 44c3fffab: `A50_UFS_ALLOW_USERDATA` with the range in `tools/m52/userdata.flags` (LUN 0 blocks 0x1c8700-0xee42ff).
For M5.3: the baseline mounts userdata with `discard`; UNMAP stays blocked (sd disables discard after the first refused UNMAP, UNVERIFIED on 6.18 until M5.3 shows it).
