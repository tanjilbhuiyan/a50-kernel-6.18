# M7.3 — Mali kbase r26p0 port
Status: in-progress · Milestone: M7 · Needs phone: build no / test yes · Depends: M7.1

## Scope

Forward-port the audited kbase r26p0 interface required by the unchanged
vendor libraries. Preserve native/compat ioctl layouts, allocation/import,
cache maintenance, job submission and synchronization. Reuse 6.18-native
facilities where semantics match; do not substitute an incompatible driver
ABI for the fixed userspace contract.

Prove clock/power/address-space prerequisites before GPU jobs. Keep the
six unsupported reserved/secure ION heaps explicit; add support only with
evidenced requirements and correct backing/protection semantics.

## Acceptance criteria
- [ ] Reproducible source/config and expected /dev/mali0 ABI availability.
- [ ] Measured allocation/import/query/sync and job paths pass meaningful checks.
- [ ] Real GPU execution verified with errors/limits recorded.
- [ ] USB/storage/runtime regression checks and clean stock restore/fsck.

## Progress

- **G0/G0b (2026-11-16):** the GPU is powered, clocked and responding: Mali-G72 r0p1 (`GPU_ID 0x62210010`), 3 shader
  cores, 8 address spaces. `PLL_G3D` locked at **260 MHz**, fixed (lowest DVFS step; DVFS needs ACPM). No clock or
  power-domain work is needed before G1. G0 declined the path because its gate rule was too strict; G0b fixed the
  rule. No faults; restores clean. [G0 log](../log/2026-11-16-M7.3-g0-gpu-probe.md). Next: G1, the kbase r26p0 port
  with a fixed-clock platform layer.
- **G1 sizing (2026-11-16, host):** Samsung kbase imported on WIP branch `a50-m73-g1-wip`. The core includes Samsung's
  Exynos platform headers unconditionally (~480 references), and Samsung adds ioctls 42-44 (SLSI boost flags). So the
  port keeps Samsung's source with a shimmed fixed-clock Exynos platform layer. Details in the G0 log.
