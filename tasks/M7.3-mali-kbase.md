# M7.3 — Mali kbase r26p0 port
Status: done (measured ordinary paths; limits below) · Milestone: M7 · Needs phone: build no / test yes · Depends: M7.1

## Scope

Forward-port the audited kbase r26p0 interface required by the unchanged
vendor libraries. Preserve native/compat ioctl layouts, allocation/import,
cache maintenance, job submission and synchronization. Reuse 6.18-native
facilities where semantics match; do not substitute an incompatible driver
ABI for the fixed userspace contract.

Prove clock/power/address-space prerequisites before GPU jobs. Keep the
six unsupported reserved/secure ION heaps explicit; add support only with
evidenced requirements and correct backing/protection semantics.

## Acceptance criteria
- [x] Reproducible source/config and expected /dev/mali0 ABI availability.
- [x] Measured allocation/import/query/sync pass stock-controlled native/compat G2h checks; real stock-Mali jobs/presentation verified by G2f/G2g (limits below).
- [x] Real GPU execution verified with errors/limits recorded (G2f visible stock-Mali UI; CPU-copy presentation).
- [x] USB/storage/runtime regression checks and clean stock restore/fsck (G2f).

## Remaining limits and integration follow-up

User-import cache sync returns EINVAL on stock and target. Six reserved/secure ION heaps remain unsupported.
Standalone `test_egl`'s userspace crash remains unresolved. Fixed 260 MHz operation does not provide DVFS.
G2h's phablet session exits with status 1 before LightDM starts a greeter; at 300 seconds transient user-manager
and greeter-session jobs remain, and at 330 seconds systemd is degraded with two failed units/one job.
LightDM remains active, userdata rw and display/GPU continue without recorded faults; this does not establish
a stable logged-in session. Preserve that evidence for M7.5 startup/session integration and ten-minute soak.
Unresponsive touch is M8. Next ticket is M7.4's conditional G2D decision; M7 overall is not complete.
