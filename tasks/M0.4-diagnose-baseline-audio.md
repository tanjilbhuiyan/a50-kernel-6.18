# M0.4 — Diagnose the baseline audio failure (kernel vs userspace)
Status: done (log/2026-11-02-M0.4-audio-diagnosis.md) — classification: userspace-config (playback). Microphone split off to M0.5.

## Why
M0.2 found that the baseline plays and records nothing (speaker, mic, call voice)
while Bluetooth A2DP works (`log/2026-11-02-M0-baseline-checklist.md`). S6 is a
success criterion and M1.3 cannot capture the audio HAL's ioctls while the HAL
never opens `/dev/snd`. We must know whether the fault is in the 4.14 kernel
(ABOX/TFA drivers or firmware, which the port must forward-port) or in userspace
(Android audio HAL / PulseAudio droid config). Owner decision 2026-11-02: do this
before M1.3. Suspend (also failing) is NOT part of this ticket.

## Known evidence (do not re-derive)
- pulseaudio `module-droid-card` loaded (hidl); sinks `sink.primary-out`, `sink.fast`; source `source.primary-in`; `paplay` rc=0 but no sound; sinks only go IDLE/SUSPENDED.
- Mid-playback: no RUNNING substream in `/proc/asound/card0`, `android.hardware.audio.service` (pid 3918) holds 0 `/dev/snd` fds, all `ABOX {DSIF,UAIF0-4} SPK`=0; `SPEAKER Switch`=on; tfa98xx bound at i2c `7-0034`.
- `parecord` returns exactly zero samples. Pulse log: "Failed to set voice volume." at 03:08. Android logcat showed no audio lines.
- Kernel was built with `--runtime-firmware` (ABOX/TFA firmware loaded from `/vendor/firmware` after vendor mounts); boot-time dmesg has rolled over, so this ticket needs a fresh boot log.

## Steps (record command output for each; one variable at a time)
1. Userspace layer (no reboot): in the container, is the audio HAL service registered and healthy? (`lxc-attach -n android -- lshal` or `service list`, `getprop | grep -i audio`, full `logcat -d -b all` around a `paplay`). Check what `module-droid-card` actually calls (PulseAudio verbose log: `pulseaudio -vvv` is too intrusive; prefer journal + `PULSE_LOG`).
2. Fresh kernel log (owner present, reboot): capture `dmesg` immediately after boot and again after Lomiri is up. Grep abox, calliope, tfa98xx, `Tfa9872.cnt`, `firmware`, `snd_soc`. Record whether the ABOX DSP firmware and the TFA container loaded and when. (A reboot clears the `/run/usb-moded` override: re-apply per `docs/06-workflow.md`.)
3. Discriminator that bypasses the HAL: with the HAL stopped from using the card (or in addition), set the ABOX/TFA mixer routes by hand and play a tone with `aplay -D hw:0,<n>` / `tinyplay`. If sound plays, kernel + firmware + amp are fine and the fault is userspace; if it errors or stays silent with firmware/DSP errors, the fault is in the kernel layer.
4. Classify: kernel / firmware-load / userspace-HAL / userspace-config. Revert every runtime change (mixer values, stopped services).
