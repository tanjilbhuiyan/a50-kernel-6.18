# M4.1 — All 8 CPUs online
Status: todo · Milestone: M4 · Needs phone: yes · Depends: M3

## Why
M4 DoD (docs/05-plan.md): all 8 CPUs online. Every 6.18 test so far boots one CPU only.

## Facts / unknowns
- Our config forces one CPU: `CONFIG_CMDLINE="... maxcpus=1"` (`tools/m22/a50_firstlight.fragment:30`).
- `exynos9610.dtsi` has 8 CPU nodes with `enable-method = "psci"`, and a `cpu-map`. The stock DT uses PSCI too (`reference/stock-dt/dt.dtb.0.dts:2679,2863`).
- CPU bring-up has never been tried on 6.18. Whether the secondary clusters come up without cluster power-domain or DVFS work is UNVERIFIED.
- Clocks: `clk_ignore_unused` stays until later work.

## Steps
1. Build a test image without `maxcpus=1` (no storage, USB diagnostics only).
2. Boot and report: `/sys/devices/system/cpu/online`, per-CPU boot lines, and any hang or warning.
3. If a cluster fails, reduce with `maxcpus=N`, record which CPUs come up, then fix one thing per boot.
4. Make it permanent in the defconfig on a kernel branch.

## Acceptance criteria
- [ ] `/sys/devices/system/cpu/online` reads `0-7` on 6.18.
