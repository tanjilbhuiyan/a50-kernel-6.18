# M4.6 — Thermal (TMU)
Status: done (2026-11-10) · Milestone: M4 · Needs phone: yes · Depends: M3

## Why
M4 DoD: thermal zones readable. Thermal limits should be in place before M4.7 raises CPU frequency.

## Facts / unknowns
- Stock DT: four `samsung,exynos9610-tmu` nodes, e.g. "BIG" at 0x10070000, IRQ SPI 0xe7 (`reference/stock-dt/dt.dtb.0.dts:4670-4742`).
- Mainline `drivers/thermal/samsung/exynos_tmu.c` supports up to Exynos7; 9610 needs data (gap matrix category B). Register layout from 4.14 `drivers/thermal/samsung/exynos_tmu.c`.
- On 9610, 4.14 reads temperatures only through an ACPM firmware plugin that 6.18 does not set up; owner decision 2026-11-10: read the TMU registers directly, read-only.

## Steps
1. Add 9610 data and DT nodes.
2. Boot and read every zone; compare with the baseline's `/sys/class/thermal` at a similar load.
3. Add trip points from the stock DT. Critical trip stays at the stock value.

## Acceptance criteria
- [x] All four zones readable on 6.18, with plausible values: under load BIG 59, LITTLE 45, G3D 46, ISP 45 C; baseline during its busy boot BIG 61, LITTLE 50, G3D 53, ISP 51 C (loads not identical).
- [x] Temperature rises under a CPU load and falls afterward (BIG 34 -> 59 -> 34 C).
- [x] `log/2026-11-10-M4.6-thermal.md`.

## Result
Read-only TMU driver on branch `a50-thermal` (owner decision 2026-11-10: direct register reads, not ACPM). Only the stock 115 C "hot" trip, which takes no action. The CURRENT_TEMP field layout is inferred, consistent with load behaviour. Cooling (frequency limits) is out of scope with cpufreq dropped.
