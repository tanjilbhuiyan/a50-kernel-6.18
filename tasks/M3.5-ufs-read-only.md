Status: done (log/2026-11-07-M3.5-ufs.md; acceptance reworded 2026-11-08) · Milestone: M3 · Needs phone: yes · Depends: M3.3, M3.4

## Why
The rootfs (`/data/ubuntu.img`) lives on UFS. Gap matrix (docs/04-gap-matrix.md:30): mainline ufs-exynos, add a 9610 variant
(PHY/sysreg data).

## SAFETY (non-negotiable, CLAUDE.md rule 5)
UFS also holds EFS, SEC_EFS, CPEFS, PARAM and the bootloader. Until reads are proven:
- no filesystem is mounted read-write; the initramfs sets every block device read-only (`blockdev --setro`) before anything else;
- check, before the first boot, whether the mainline UFS core writes PERSISTENT device attributes at init (e.g. the reference-clock
  attribute bRefClkFreq when the DT value differs from the device's). The DT must state the value the device already has
  (26 MHz per the 4.14 driver; UNVERIFIED) so no write happens. Record the evidence in the log.

## Steps
1. 9610 variant data from the 4.14 driver; DT nodes (ufs, phy, sysreg) from the stock DT.
2. Boot with readout; enumerate LUNs and partitions.
3. Read-only verification: sha256 of the first 53,624,832 bytes of the `boot` partition must equal 7d5855ef... (baseline boot.img).
