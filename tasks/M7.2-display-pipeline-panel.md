# M7.2 — DPU20 display pipeline and panel
Status: in-progress · Milestone: M7 · Needs phone: build no / test yes · Depends: M7.1

## Scope

M7.1 found that the panel is powered by GPIOs and that S2MPB03 feeds only cameras, so M4.4/M4.3 are not display
prerequisites ([audit](../log/2026-11-14-M7.1-display-gpu-audit.md) section 4). Follow its boots D0-D4: read-only state
probe, minimal frame-update handover, fbdev core, SysMMU attach with a boot-framebuffer identity region, blank/unblank.

Implement the audited DECON/DPP/DSIM/panel path, preserving the stock
composer ABI. Enable one resource/driver stage per boot. Resolve required
I2C/regulator prerequisites before using them; do not boot the known
freezing M4.4 nodes as a shortcut. Keep clean driver and diagnostic source
separate and retain the working USB/storage/runtime setup.

Attach the audited display master to SysMMU only with a defined IOVA,
buffer-lifetime and fault-handling plan. Provider probe alone is insufficient.

## Acceptance criteria
- [ ] Required display nodes/clocks/regulators/panel probe with evidence.
- [ ] Stock composer opens its expected nodes and observed ioctl paths work.
- [ ] First display output and real DMA/fence behavior verified; faults reviewed.
- [ ] USB SSH/guard retained, inputs/source recorded and stock restore/fsck clean.

## Progress

- D0 (2026-11-14): the probe ran read-only. The DISPAUD domain is on, but the TOP→DISPAUD clock gate is manual-off,
  switched off by the 6.18 clock init: the CMU range is 0x8000, so the driver forces manual mode on every gate. The
  display blocks were not read. No timed dump (premature manual recovery); restore and post-flight passed, fsck clean.
  [D0 log](../log/2026-11-14-M7.2-d0-display-probe.md). Next: D0b, which enables only `gout_cmu_dispaud_disp`, then
  the same reads.
- D0b (2026-11-16): enabling only `gout_cmu_dispaud_disp` plus the read-only reads ran to the 431 s timed dump with no
  logged fault; Android ran. No USB gadget came up (cause unverified), and the dump window (382-431 s) misses the
  probe lines, so the register values are still unknown. Restore and post-flight passed, fsck clean.
  [D0b log](../log/2026-11-16-M7.2-d0b-display-clock.md). Next: D0c (probe re-prints at about 400 s), optionally after
  a D0 control run on this setup.
- D0c (2026-11-16): the display state was captured in the dump. DECON is enabled in command mode with the TE trigger
  masked, window 3 is fed by IDMA0 from the boot framebuffer at `0xca000000`, and DSIM is configured for 1080x2340.
  The DPU SysMMU clock is off. Restore and post-flight passed, fsck clean.
  [D0c log](../log/2026-11-16-M7.2-d0c-display-state.md). Next: D1 (SysMMU clock on, pattern, one frame update).
