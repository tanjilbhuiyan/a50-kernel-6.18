# M7.2 — DPU20 display pipeline and panel
Status: todo · Milestone: M7 · Needs phone: build no / test yes · Depends: M7.1

## Scope

M7.1 found that the panel is powered by GPIOs and that S2MPB03 feeds only cameras, so M4.4/M4.3 are not display
prerequisites ([audit](../log/2026-11-14-M7.1-display-gpu-audit.md) section 4). Follow its boots D0-D4: read-only state
probe, minimal frame-update handover, fbdev core, SysMMU attach with a boot-framebuffer identity region, blank/unblank.

Implement the audited DECON/DPP/DSIM/panel path, preserving the stock
composer ABI. Enable one resource/driver stage per boot. Resolve required
I2C/regulator prerequisites before using them; do not boot the known
freezing M4.4 nodes as a shortcut. Keep clean driver and diagnostic source
separate and retain the working USB/storage/runtime setup.

Attach the audited display master to SysMMU only with a defined IOVA,
buffer-lifetime and fault-handling plan. Provider probe alone is insufficient.

## Acceptance criteria
- [ ] Required display nodes/clocks/regulators/panel probe with evidence.
- [ ] Stock composer opens its expected nodes and observed ioctl paths work.
- [ ] First display output and real DMA/fence behavior verified; faults reviewed.
- [ ] USB SSH/guard retained, inputs/source recorded and stock restore/fsck clean.
