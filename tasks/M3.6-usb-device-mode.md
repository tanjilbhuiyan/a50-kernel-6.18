# M3.6 — USB device mode (DRD + PHY + gadget)
Status: done (2026-11-09) · Milestone: M3 · Needs phone: yes · Depends: M3.3, M3.4

## Why
A direct link to the laptop. Gap matrix (docs/04-gap-matrix.md:32-34): dwc3-exynos + phy-exynos5-usbdrd need 9610 data; sm5713
(USB-C role/VBUS) is category C.

## Facts / unknowns
- Known baseline issue: the laptop's USB-C port is detected as a PD charger on 4.14, no gadget link (docs/02-baseline.md
  "Known issues" #1). Whether this is the sm5713/PD policy or the cable/port on 6.18 is UNVERIFIED.
- First attempt bypasses sm5713: DT `dr_mode = "peripheral"`, VBUS assumed present.
- The sm5713 needs no setup for device mode: its MANUAL_SW reads 0 after S-Boot, but CFG1 selects automatic switching and it routes USB by itself (no-switch test, 2026-11-09). The 2026-11-08 "switch is open" theory was wrong.
- The baseline powers USB from LDO12 (0.85 V), LDO13 (1.8 V), LDO14 (3.0 V). On 6.18 all three read on, byte-identical to the baseline (Test 4). PMIC access is through ACPM firmware IPC.
- Owner decision 2026-11-08: USB-C cable only.

## Steps
1. 9610 data for dwc3-exynos and the USB DRD PHY; DT nodes.
2. configfs gadget (RNDIS + ACM) from the initramfs.
3. Test with the laptop.
4. Read LDO12-14 on 6.18 through ACPM IPC, read-only (no PMIC writes); compare with the baseline.
5. If a rail is off: enabling it is a separate test, with the owner's approval. (2026-11-08: all three are on.)
6. Read the PHY and CMU_USB registers on a working 4.14 kernel (test kernel with a built-in read-only dump; the baseline refuses modules), and compare them with 6.18.

## Acceptance criteria
- [x] The laptop enumerates the gadget (`lsusb`, dmesg on the laptop).
- [x] RNDIS ping or ACM shell works (ACM shell, 6/6 commands).
- [x] `log/<date>-M3.6-usb.md` (`log/2026-11-08-M3.6-usb.md`).

## Result
The fix is `LINK_CTRL` PIPE3 override in the 9610 PHY init (Samsung's `phy_exynos_usb_v3p1_pipe_ovrd`), kernel commit `36fdc0b53` on `a50-usb` (`reference/m36-usb/0003-*.patch`). Found by comparing against the registers of a working phone. Not needed: sm5713 writes, keeping the PHY clock on, clearing GUSB2PHYCFG bit 30, disabling SUSPHY.

## Open observations (not blocking)
- One clean-image run (2026-11-09 18:20) passed the ACM shell, then stopped responding before its timed dump (no log, cause unknown); the next run of the same image completed normally. Watch for it in M3.7.
- Gadget is ACM only. RNDIS for telnet over USB belongs to M3.7.
- `clk_ignore_unused` and the placeholder USB supplies stay until PMIC/clock work (M4).
