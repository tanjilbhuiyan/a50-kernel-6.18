# M2.4 — First light on the phone
Status: in-progress: attempt 1 failed (static warning screen, no output), baseline restored and verified; log/2026-11-04-M2.4-first-light.md · Milestone: M2 · Needs phone: yes · Depends: M2.1, M2.2, M2.3, M1.5

## Why
M2 Definition of Done: a 6.18 kernel runs on the A50 and leaves evidence.

## Steps (owner present; fallback images ready and hash-checked first)
1. TWRP: back up current DTB + DTBO partitions (`dd` → laptop, sha256 must equal stock).
2. TWRP: write our DTB/DTBO (M2.3) with dd + read-back hash.
3. Download mode: flash BOOT with the first-light boot.img (M2.2).
4. Boot; observe screen (banner on simplefb?) and timing.
5. Reboot into baseline (restore BOOT + stock DTB/DTBO), read pstore.

## Backup and rollback plan (written 2026-11-04; the two OWNER DECISIONS at the end must be answered before any flash)

### Procedure with go/no-go points
0. Preconditions: battery >= 60% (phone was 100%), phone on the baseline, root SSH works, `tools/m24_preflight.sh <ip>` passes. DRY RUN of the rollback channel first: power off, enter Download mode, `heimdall detect` (and `heimdall print-pit` to confirm the DTB/DTBO/BOOT names), leave Download mode without flashing. Stop if Download mode or heimdall does not work.
1. Flash (one Download-mode session, all small images so the <=67 MB Heimdall rule holds): `heimdall flash --DTB reference/dt-6.18/images/dt.img --DTBO reference/dt-6.18/images/dtbo.img --BOOT src/m22/artifacts/boot-firstlight.img --no-reboot` (method A below).
2. Boot (owner restarts with Vol Down+Power). Observe and record with timings and phone photos: Samsung logo and warning, any vibration, whether the screen goes black or shows text, the banner/countdown on the framebuffer, whether the phone resets by itself.
   - Text appears: leave it for the 45 s countdown; the init then panics on purpose.
   - Screen stays black or the logo loops: wait ~2 minutes, then roll back (step 4). That is a valid result (S-Boot or kernel rejected the images); capture exactly what was seen.
3. Second boot to read the crash log: if the phone restarts by itself after the panic, it boots the first-light image again and the init prints the previous boot's pstore records. If it hangs, hold Vol Down+Power ~10 s (hard reset) and let it boot the same image again; whether DRAM survives that reset is part of the answer. Do not change any image between the two boots (one variable).
4. Roll back: Download mode (hold Vol Up+Vol Down while plugging USB; if looping, interrupt as in M1.4), `heimdall flash --DTB reference/stock-images/dt.img --DTBO reference/stock-images/dtbo.img --BOOT baseline/ut-26.04-2026-10-19-aa17rf2/boot.img --no-reboot`, restart with Vol Down+Power.
5. Verify the baseline: root SSH works, `uname -r` = 4.14.194, Lomiri and the Android container running, the four fix units active, and read-backs from the running phone: `/dev/disk/by-partlabel/dtb`, `dtbo` = stock hashes, BOOT first 53,624,832 B = 7d5855ef…, i.e. `tools/m24_preflight.sh <ip>` passes again. Note: Samsung's /proc/last_kmsg may be garbled afterwards (our ramoops used its region).
6. Write `log/<date>-M2.4-first-light.md` with observations, photos, hashes, timings, and evaluate the M2 DoD in STATUS.md.

### Failure matrix
| What goes wrong | Likely sign | Recovery |
|---|---|---|
| S-Boot rejects dt.img/dtbo.img (stale Samsung signature, AVB footer, DT content) | bootloop at the Samsung logo, never any kernel text | Download mode, step 4 (Heimdall), nothing else touched |
| Kernel never starts (load address misalignment, wrong DT, console) | black screen after the logo, no text | step 4; next variable would be a 2 MiB-aligned `kernel_addr` (separate test) |
| Kernel runs but no text (framebuffer format or address wrong) | black screen but the phone stays up | step 4; pstore/second boot may still show the log is not readable without a screen: then try swapped `a8b8g8r8` as the next single variable |
| Phone hangs after the deliberate panic (PSCI reset unverified) | frozen text screen | hard reset (Vol Down+Power); expected, not a failure of the test |
| Download mode unreachable | key combo does not work | TWRP via recovery key combo, `adb`, dd stock partitions with read-back hash; last resort: stock firmware zip |
| Heimdall write fails mid-way | error from heimdall, phone not booting | Download mode again; DTB/DTBO/BOOT are small, retry; the dumps in `baseline/m24-pre-flash/` double-check the references |

### Method choice (owner decision 1)
- A (recommended): Heimdall for DTB + DTBO + BOOT in one session, rollback symmetrical with the same tool (proven for BOOT in M1.4, small images). Cannot read the partitions back before booting; verification is the heimdall success plus the post-rollback hashes.
- B (as in the original steps): TWRP + adb + dd for DTB/DTBO with a read-back hash, Heimdall only for BOOT. Gives a verified write, costs a TWRP session and an extra reboot, and TWRP/adb from this laptop has not been exercised in this project yet.
### Timing (owner decision 2)
About 45-60 minutes with the owner at the phone, USB cable in, phone charged. Photos of the screen recommended at each observation point.
