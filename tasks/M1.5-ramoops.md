# M1.5 — Working ramoops/pstore crash log
Status: todo · Milestone: M1 · Needs phone: yes · Depends: M0, M1.1

## Why
No practical UART (R4). First light (M2) and every early-boot failure depend
on reading the previous boot's kernel log after reboot.

## Inputs (from live DT, `docs/03-kernel-contract.md` §4)
`debug_snapshot/log_pstore` at 0xf9d10000 size 0x200000; `log_kernel` 0xf9010000
size 0x200000; baseline has `CONFIG_PSTORE_RAM=y`, `CONFIG_PSTORE_CONSOLE=y`.

## Steps
1. As root on baseline: `ls /sys/fs/pstore`; mount pstore if needed. Check what backend is registered (`dmesg | grep -i pstore`).
2. Trigger a controlled panic (`echo c > /proc/sysrq-trigger`, owner present), reboot to baseline, read `/sys/fs/pstore/console-ramoops*` / `dmesg-ramoops*`.
3. If nothing persists: determine whether S-Boot clears the region; test the `log_kernel` region; document.
4. Record the exact `ramoops` DT node (address, size, record/console sizes) to reuse in M2.1.

## Acceptance criteria
- [ ] After a forced panic, the previous boot's log is readable after reboot (path + excerpt in log), **or** documented proof it is not possible and an alternative chosen.
- [ ] Exact ramoops DT node text recorded for M2.1.
- [ ] `log/<date>-M1.5-ramoops.md`.
