# M2.1 — A50 device tree for 6.18 (first-light subset)
Status: done (log/2026-11-01-M2.1-dt.md) — framebuffer pixel format accepted as a documented risk by the owner (2026-11-02); resolve in M2.4 · Milestone: M2 · Needs phone: no · Depends: M1.2 (M1.5 for ramoops node)

## Why
6.18 bindings differ from Samsung's 2019 DT; the kernel needs a DT it understands.
First light needs only the minimum.

## Inputs
- Live DT dump `reference/live-dt-compatibles.tsv`; stock `reference/stock-images/dt.img` + `dtbo.img` (idx 5).
- Samsung DTS: `src/samsung-a50-4.14-aa17rf2/arch/arm64/boot/dts/exynos/exynos9610.dts`, `samsung/exynos9610-a50_*`.
- Mainline templates: `exynos850.dtsi`, `exynos850-e850-96.dts` in `src/ack-6.18` / `src/linux-6.18.60`.
- Mainline-after-6.18 pinctrl 9610 data (backport), LKML clock series (Chimac v3, Jul 2026).

## Scope (first light only)
cpus (8, PSCI), GIC, arch timer, memory, reserved-memory (incl. ramoops from M1.5),
`simple-framebuffer` @0xca000000 (1080×2340; format/stride from bootloader — verify),
fixed-rate oscillator clock, chosen/stdout.

## Steps
1. Write `exynos9610.dtsi` (SoC minimum) + `exynos9610-a50.dts` (board) in the 6.18 tree on a branch.
2. Determine framebuffer stride/format (Samsung decon DT, `s3cfb.bootloaderfb` handling in 4.14 source).
3. `make dtbs` + `dt-validate`/`dtbs_check` clean for these nodes.

## Acceptance criteria
- [x] DTB builds; `dtbs_check` has no errors for the included nodes.
- [x] Every node cites its source (Samsung DTS line or mainline template) in comments.
- [x] Framebuffer parameters justified from source, not guessed.
- [x] Commit in the kernel tree + `log/<date>-M2.1-dt.md`.
