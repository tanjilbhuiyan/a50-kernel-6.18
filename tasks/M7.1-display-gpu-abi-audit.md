# M7.1 — Display/GPU ABI audit and implementation design
Status: done (2026-11-14; log/2026-11-14-M7.1-display-gpu-audit.md) · Milestone: M7 · Needs phone: saved evidence first · Depends: M6.4

## Scope

Map the actual stock composer and Lomiri contracts before porting display
or GPU code. Start with [display](../reference/contract/display.md),
[Mali](../reference/contract/mali.md), donor sources and the final M6 config.
Record ioctl layouts/compat, dma-buf/fence ownership, IOVA needs, firmware,
clocks, regulators, power domains and the bootloader display state.

Decide how native 6.18 facilities fit the fixed vendor ABI. M6 verified
heap-0 CPU allocation and a DPU SysMMU v7.2 provider probe only. Actual DMA,
GPU execution and the other six heaps remain unverified. Identify the
M4.4 I2C/M4.3 S2MPB03 prerequisites before display power changes. Preserve
USB SSH, the userdata guard and the working headless Android startup.

## Acceptance criteria
- [x] Evidence-backed interface/resource map and minimal port design recorded.
- [x] First boot variables and rollback method defined; hardware prerequisites explicit.
- [x] G2D demand assessed from captures and source, with unknowns labelled.
- [x] Remaining legacy cgroup-profile warnings and TEEGRIS deferral assessed for M7 consumers.

No M7 hardware enablement is part of this audit ticket.

## Result

[Audit and design](../log/2026-11-14-M7.1-display-gpu-audit.md). Display stays on fbdev with the stock `S3CFB_*` ABI;
the panel is a command-mode MIPI panel, so the first output needs a DECON frame update (boot D1). Panel power is
GPIO-only and S2MPB03 feeds cameras only, so display does not depend on M4.4/M4.3. Mali runs at the bootloader's
clock (DVFS needs ACPM). The composer already starts on simplefb, so the process alone proves nothing. G2D waits for
evidence that the composer needs it. Boot ladder: D0-D4 (display), G0-G2 (GPU).
