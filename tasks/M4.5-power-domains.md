# M4.5 — Power domains
Status: in-progress · Milestone: M4 · Needs phone: yes · Depends: M3

## Why
Listed in M4 (docs/05-plan.md); later milestones (display, GPU, audio, camera) need power domains modelled.

## Facts / unknowns
- Mainline `drivers/pmdomain/samsung/exynos-pm-domains.c` matches `samsung,exynos4210-pd` and `exynos5433-pd`. 9610 domain register layout is UNVERIFIED (gap matrix: DT + data).
- Stock DT has `dbgdev-pd-*` nodes (cam, isp, vipx2, g2d, g3d, dispaud, mfc; `reference/stock-dt/dt.dtb.0.dts:2048`); the real domain definitions still need finding.
- Our kernels run with `CONFIG_PM` off. **Before enabling PM**, UFS hibern8/PWM tables must be ported (carried forward from `log/2026-11-07-M3.5-ufs.md`), or UFS may break.
- Risk: powering off a domain something still uses can hang the phone. Domains stay on at first.

## Steps
1. Find the 9610 domain registers (4.14 `exynos-pd`, `cal-if`); record them.
2. Add DT and data; report each domain's state read-only, with no power-off.
3. Decide with the owner whether to enable `CONFIG_PM` and runtime power-off in M4 or defer it to M12.

## Acceptance criteria
- [ ] Domains registered; `/sys/kernel/debug/pm_genpd/pm_genpd_summary` matches the states the hardware reports.
- [ ] Decision on `CONFIG_PM` recorded.
- [ ] `log/<date>-M4.5-power-domains.md`.
