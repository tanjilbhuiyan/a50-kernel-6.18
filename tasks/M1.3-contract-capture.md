# M1.3 — Capture the vendor kernel ABI (contract capture)
Status: in-progress (log/2026-11-02-M1.3-contract-capture.md) · Milestone: M1 · Needs phone: yes · Depends: M0, M0.4

## Why
`docs/03-kernel-contract.md` §2b lists device nodes; we must know the exact
ioctls/sysfs the stock vendor uses so forward-ported drivers and the ION shim
keep them (risks R2, R3, R6).

## Inputs
Baseline phone with root (M0.1). Nodes in scope: `/dev/mali0`, `/dev/ion`,
`/dev/ionfd2phys`, `/dev/graphics/fb*`, `/dev/g2d`, `/dev/fimg2d`, ABOX/ALSA
(`/dev/snd/*`, `/dev/seiren`), `/dev/scsc_*`, `/dev/mx_*`, `/dev/umts*`,
`/dev/ipc`, `/dev/smd`, `/dev/drb`, `/sys/class/power_supply/*`.

## Steps
1. Map openers: for each node, `ls -l /proc/*/fd 2>/dev/null | grep <node>` → process names (inside and outside the LXC container).
2. Record ioctl numbers per process: kernel tracing on the baseline
   (`/sys/kernel/tracing`, event `syscalls/sys_enter_ioctl` filtered by pid) during:
   boot to UI, 30 s UI use, audio playback, a call, Wi-Fi reconnect.
   If syscall tracepoints are not enabled in the baseline config, record that and use `strace -f -e ioctl` on the HAL processes instead.
3. Decode ioctl numbers against `src/samsung-a50-4.14-aa17rf2/include/uapi` and driver headers.
4. Write `reference/contract/<subsystem>.md`: node, opener, ioctl cmd (hex + name), struct size.

## Acceptance criteria
- [ ] Contract files exist for: mali, ion, display (fb/decon), audio, wifi/bt (scsc), modem.
- [ ] Each lists opener process and decoded ioctl set observed.
- [ ] Unobserved-but-present nodes listed as "not used in tested scenarios".
- [ ] `log/<date>-M1.3-contract-capture.md`.
