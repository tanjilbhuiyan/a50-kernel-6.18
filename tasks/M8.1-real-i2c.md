# M8.1 — Real I2C without freezing 6.18 (unblocks M4.4)
Status: done (2026-11-18; log/2026-11-18-M8.1-i2c.md) · Milestone: M8 · Needs phone: yes · Depends: M4.4

## Scope
Make the Exynos 9610 `samsung,s3c2440-i2c` controllers probe and transfer on 6.18. M4.4 found that enabling real I2C
freezes the kernel early with no Download mode and no log: test 2 (I2C 0/1/3/4/6, PWM, keys) and test 3 (only I2C 0
and 1 on gpp0 pins) both hung (`log/2026-11-10-M4.4-buses.md`; `docs/08-open-questions.md` #8). The cause is unverified.
The touch controller is on `i2c@13870000` (`reference/live-dt-compatibles.tsv` line 157), and S2MPB03 on
`i2c@13860000`, so M8.2 and the rest of M4.4 depend on this. One bus at a time; no writes to unknown slave devices
(probe/read only until a consumer driver is in place).

## Acceptance criteria
- [x] Cause of the M4.4 freeze identified with evidence (clock gate, pinctrl, interrupt, power domain or driver), or
      the freeze reproduced and bisected to a single DT/driver variable.
- [x] `i2c@13870000` probes on 6.18 and a read-only transfer to address 0x48 is answered (or the failure is explained).
- [x] The remaining enabled buses probe without regressions; M4.4's keys/PL330/S2MPB03 items re-evaluated.
- [x] Stock restore/fsck clean; kernel changes on the clean stack and exported to `patches/`.

Result (2026-11-18): bisected to the 6.18 CMU_PERI clock driver (T1 vs T3); ADR-0007 keeps CMU_PERI in the
bootloader's state with fixed PERI clocks. Buses 0/1/3/4/6 probe on the clean stack (T4, patches 0046-0048); 0x48 NACKs
(touch controller presumably unpowered: M8.2).
