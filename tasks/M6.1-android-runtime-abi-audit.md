# M6.1 — Android runtime and kernel ABI audit
Status: done · Milestone: M6 · Needs phone: no (saved evidence first) · Depends: M5

## Why
M5 boots Ubuntu and provides USB SSH, but Android is STOPPED. Before changing
the kernel/container configuration, identify the actual first blockers from
the tested system and the stock-vendor contract.

## Inputs
- M5.4 log and reference/m54-usb-ssh/, especially the tested config manifest,
  USB SSH lxc-info output and current checker comparison.
- docs/03-kernel-contract.md, reference/contract/, stock-vendor init/fstab
  extracts and baseline Halium ramdisk/rootfs backup.
- Clean source a50-userdata/c7bde3fe3; diagnostic test base f0618ab59.

## Steps
1. Map existing binder, ashmem, ION, sync/wakelock, IOMMU and namespace/cgroup
   consumers to current kernel config and expected node paths. Record absent
   interfaces and distinguish config-only work from a driver/ABI port.
2. Inspect Android mount/start units and LXC config. Explain the protected EFS
   mount failure and plan readonly mounts or userdata-backed runtime overlays
   without modifying EFS/vendor contents. Prefer native 6.18/cgroup v2 paths.
3. Record a bounded bring-up sequence and the first one-variable test for M6.2.
   Unknown requirements remain unverified until source or measurements prove them.

## Acceptance criteria
- [x] Evidence-linked table of required interfaces, current status, owners and strategy.
- [x] Android mount/cgroup/config blockers classified; no protected-partition writes proposed.
- [x] Dated log and reproducible first test plan; no M6 implementation started as part of this audit.

## Result

[Audit and first-test procedure](../log/2026-11-11-M6.1-android-runtime-abi-audit.md).
The M5.4 kernel lacks BinderFS and Android startup stops at a mount-unit
dependency. The EFS write denial is confirmed. The mount unit's exact exit
command remains unverified. The archived Android 11 config establishes legacy
cgroup expectations for M6.4 to test against the cgroup v2 host. M6.2 starts with
an isolated BinderFS control and candidate using the working M5.4 USB setup.
