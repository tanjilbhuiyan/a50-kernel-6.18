# M1.4 — Does S-Boot boot a compressed kernel Image?
Status: todo · Milestone: M1 · Needs phone: yes · Depends: M0, M1.1

## Why
Risk R1: BOOT is 57,671,680 bytes; baseline already uses 53.6 MB with an
uncompressed Image (42.8 MB). A 6.18 kernel with Halium ramdisk may not fit
uncompressed.

## Steps (one variable: kernel compression only)
1. From M1.1 outputs, build `Image.gz` (and `Image.lz4` if the 4.14 tree supports it) of the **same** baseline kernel.
2. Repack boot.img with identical header fields and the baseline ramdisk; only the kernel payload changes.
3. Flash BOOT (Heimdall), boot, check `uname -a` and that UT reaches Lomiri.
4. Restore baseline boot.img if it fails (fallback ready before flashing).

## Acceptance criteria
- [ ] Result recorded: gzip boots yes/no; lz4 boots yes/no (if tested).
- [ ] If no compression works: R1 mitigation updated in `docs/07-risks.md` (size budget per milestone).
- [ ] `log/<date>-M1.4-compressed-image.md`; baseline restored or confirmed equivalent.
