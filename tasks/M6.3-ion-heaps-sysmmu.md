# M6.3 — Legacy ION ABI, Exynos heaps and SysMMU preparation
Status: done (measured heap 0; provider preparation) · Milestone: M6 · Needs phone: build no / test yes · Depends: M6.1

## Why
Stock gralloc uses ION_IOC_ALLOC/HEAP_QUERY and Samsung DMA_BUF_IOCTL_TRACK/
UNTRACK. These interfaces are absent from native 6.18 dma-buf heaps. Preserve
the stock ABI while reusing native infrastructure where it fits.

## Steps
1. Map heap IDs, sizes, flags, address/IOMMU needs and compat ioctl layouts from
   reference/contract/ion.md, Samsung source and baseline evidence. Record a
   minimal ABI/heap implementation design before coding.
2. Implement the planned legacy ION compatibility frontend and required Exynos
   heaps. Preserve observed semantics, allocation/free lifetime and sync behavior.
   Add meaningful boundary/lifetime tests for the actual port.
3. Prepare the needed Exynos SysMMU DT/config integration from source evidence;
   validate bindings and probes. Distinguish CPU allocation/map checks from
   real device DMA, which may only be exercised with M7 consumers.
4. Replay captured allocator requests on 6.18 and verify heap query and
   allocation results, dma-buf bookkeeping, cleanup and memory stability.

## Acceptance criteria
- [x] Heap/ABI mapping and design recorded with evidence; no vendor changes.
- [x] Required query/allocation/compat and Samsung dma-buf paths exercised successfully.
- [x] SysMMU integration scope and untested hardware paths explicit; no premature GPU claim.
- [x] USB SSH retained; log/config/hashes/commits and clean restore evidence.

## Progress

The baseline heap table and allocator request payloads are captured. The
frontend implements the measured system-heap requests using ACK's cached
and uncached DMA heaps. All 32 captured allocations, query validation,
copyout cleanup and tracking/dup/fork/exec tests passed on AArch64 and
AArch32. Debugfs returned to zero exported buffers. Native Exynos SysMMU
config control passed, then the isolated DPU provider bound and reported
hardware version 7.2. All four boots restored stock DTB/DTBO/BOOT with
post-flight hashes verified and baseline init's saved fsck clean. There
were 224 successful captured allocation replays across the four boots.

Scope: heap 0 covers every captured normal-UI allocation. The other six
reserved/secure heaps are unsupported and omitted from the advertised
table. M6.4 must check the real allocator service against this subset;
newly evidenced requirements need further heap work. No master is attached
to SysMMU yet. Actual device DMA, the other controllers, secure access and
suspend/resume remain for their consumer milestones; this ticket establishes
provider preparation only.
