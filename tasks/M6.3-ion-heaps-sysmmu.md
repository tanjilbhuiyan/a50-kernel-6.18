# M6.3 — Legacy ION ABI, Exynos heaps and SysMMU preparation
Status: todo · Milestone: M6 · Needs phone: build no / test yes · Depends: M6.1

## Why
Stock gralloc uses ION_IOC_ALLOC/HEAP_QUERY and Samsung DMA_BUF_IOCTL_TRACK/
UNTRACK. These interfaces are absent from native 6.18 dma-buf heaps. Preserve
the stock ABI while reusing native infrastructure where it fits.

## Steps
1. Map heap IDs, sizes, flags, address/IOMMU needs and compat ioctl layouts from
   reference/contract/ion.md, Samsung source and baseline evidence. Record a
   minimal ABI/heap implementation design before coding.
2. Implement the planned legacy ION compatibility frontend and required Exynos
   heaps. Preserve observed semantics, allocation/free lifetime and sync behavior.
   Add meaningful boundary/lifetime tests for the actual port.
3. Prepare the needed Exynos SysMMU DT/config integration from source evidence;
   validate bindings and probes. Distinguish CPU allocation/map checks from
   real device DMA, which may only be exercised with M7 consumers.
4. Replay captured allocator requests on 6.18 and verify heap query and
   allocation results, dma-buf bookkeeping, cleanup and memory stability.

## Acceptance criteria
- [ ] Heap/ABI mapping and design recorded with evidence; no vendor changes.
- [ ] Required query/allocation/compat and Samsung dma-buf paths exercised successfully.
- [ ] SysMMU integration scope and untested hardware paths explicit; no premature GPU claim.
- [ ] USB SSH retained; log/config/hashes/commits and clean restore evidence.
