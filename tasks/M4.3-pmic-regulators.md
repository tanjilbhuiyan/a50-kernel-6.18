# M4.3 — S2MPU09 and S2MPB03 PMICs, regulators
Status: in-progress · Milestone: M4 · Needs phone: yes · Depends: M4.2, M4.4 (S2MPB03)

## Why
M4 DoD: regulators enumerated, no warnings from missing supplies. The USB supplies are still placeholders.

## Facts / unknowns
- S2MPU09 is reached through ACPM (`s2mpu09_read_reg` -> `exynos_acpm_read_reg`, 4.14 `drivers/mfd/s2mpu09-core.c:53`), channel 2. A SPEEDY driver is not needed (plan change 2026-11-10).
- Mainline has `drivers/mfd/sec-acpm.c` and `sec-common.c` (s2mpg family); S2MPU09 needs variant data. Register map: 4.14 `include/linux/mfd/samsung/s2mpu09-regulator.h`.
- Stock DT: 44 `regulator-name` entries in `reference/stock-dt/dtbo.5.dts` (from :1718). USB uses LDO12/13/14 (baseline `/sys/class/regulator`).
- S2MPB03 is on I2C at 0x56 (baseline `3-0056`), so it depends on M4.4.
- **The PMIC feeds the whole phone.** Linux may switch off regulators it thinks are unused.

## Safety rules
- First boot: read-only (no `set_voltage`, no enable or disable). Use `regulator-always-on` and `regulator-boot-on` as needed, and keep unused regulators on.
- Any PMIC write needs a separate test, with the register list shown to the owner first.

## Steps
1. Add S2MPU09 variant data and regulator ops; DT from the stock nodes.
2. Boot read-only: report every regulator's state and voltage, compare with the baseline.
3. Replace the `reg_dummy` USB supplies with LDO12/13/14; USB must still work.
4. Add S2MPB03 after M4.4.

## Progress (2026-11-10)
S2MPU09 done on branch `a50-pmic`: 35 regulators through a read-only ACPM driver. 31 of 36 listed match the baseline; the 5 that differ are DVFS rails at the bootloader's level. USB runs on the real LDO12/LDO14 and the ACM shell passes.
Still open: S2MPB03 (needs a working I2C, see M4.4); the DT binding yaml; the PHY's optional `vbus` and `vbus-boost` supplies still print "using dummy regulator" (M4.8).
