# M3.2 — Readout at any time (panic hook + delayed dump)
Status: todo · Milestone: M3 · Needs phone: yes · Depends: M3.1

## Why
The Test 19 readout dumps once at late_initcall_sync, before init runs. Failures in init, in drivers that probe late, or panics
are invisible. The only proven channels are the PMU SWRESET loop and the DSS dump + software reboot to Download mode
(log/2026-11-04-M2.4-diag-build.md, Tests 10 and 19).

## Steps
1. Panic notifier: on panic, run the DSS dump and reboot to Download mode (same code as A50_DIAG_DUMP_DSS).
2. Delayed dump: kernel parameter (e.g. `a50diag.dump_after=<s>`) that dumps from a workqueue after N seconds and reboots to
   Download mode; 0 = off. The boot.img cmdline carries it, so no rebuild per experiment.
3. Make the reader a tool: `tools/m32_read_618.sh IP OUT` (extract BEGIN/END, redact identifiers).
4. Tests: (a) forced panic from the tiny initramfs -> panic text read back; (b) dump_after=20 -> init's output read back.

## Acceptance criteria
- [ ] A forced panic's message is read back.
- [ ] A delayed dump shows the initramfs init's own output.
- [ ] Tool committed; `log/<date>-M3.2-readout.md`.
