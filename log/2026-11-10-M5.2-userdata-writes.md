# 2026-11-10 M5.2 userdata writes

## Owner decisions
Back up ubuntu.img only, before any write; first writable boot approved once the backup is verified.

## Backup method (read-only)
Copying ubuntu.img from the running baseline could catch the live root filesystem mid-write. Instead: the runner shuts the baseline down cleanly (reboot to Download), then a 6.18 image mounts /userdata read-only (ro,noload) with the write guard on, and busybox httpd serves it on 192.168.2.15:5000 over USB RNDIS (busybox has no nc). tools/m52/backup_ubuntu_img.py downloads it, checks the size (6442450944) and compares sha256 with the phone's own sha256sum, then panics the phone (sysrq c) so the dump and rollback run. Image: src/m52/boot-m52-backup.img (M5.1 config, A50_HALIUM=1, dump_after 2400 as a fallback), init tools/m52/init-backup. Backup goes to ../a50-ubuntu-img-backup/ (outside the repo; ../backup is not touched).
