## Test design

`PM_WAKELOCKS` depends on `PM_SLEEP`, which requires `SUSPEND` or hibernation
callbacks in this source. The candidate enables `SUSPEND` and `PM_WAKELOCKS`.
It keeps kernel automatic sleep and hibernation disabled. Enabling PM also
enables its runtime and CPU-hotplug prerequisites, recorded in the resolved
config delta.

Both the control and candidate append runtime masks for `repowerd.service`,
`a50-enable-autosuspend.service` and `sleep.target`. The archived power
activation helper calls the Android SystemSuspend service. The Android
partition unit stays masked as in prior M6.2 tests. The control boot tests
the userspace masking setup before the candidate adds PM support. This is
an interface test for M6.2. Suspend integration remains M12.

## Build

Use the pinned Clang r584948c, Rust `1.91.1.p3`, bindgen 0.72.1 and build
identity from the [ashmem recipe](2026-11-11-M6.2-ashmem.md). Use fresh output
directories and the same test source for both builds.

Both images packed below the 57,671,680-byte BOOT limit. Their embedded
cpio archives are byte-identical to the sync build. [Input hashes](../reference/m62-wakelock/inputs.json) ·
[Control config delta](../reference/m62-wakelock/control-from-sync.txt) ·
[Candidate config delta](../reference/m62-wakelock/candidate-from-control.txt).

```bash
control=$ack/out/m62-wakelock-control
candidate=$ack/out/m62-wakelock
mkdir -p "$control" "$candidate"
cp "$ack/out/m62-sync/.config" "$control/.config"
cmdline=$(sed -n 's/^CONFIG_CMDLINE="\(.*\)"$/\1/p' "$control/.config")
"$kernel/scripts/config" --file "$control/.config" --set-str CMDLINE "$cmdline systemd.mask=repowerd.service systemd.mask=a50-enable-autosuspend.service systemd.mask=sleep.target"
kbuild=(make -C "$kernel" -j16 ARCH=arm64 LLVM=1 RUSTC="$rust_dir/bin/rustc" BINDGEN="$ack/prebuilts/clang-tools/linux-x86/bin/bindgen")
"${kbuild[@]}" O="$control" olddefconfig
cp "$control/.config" "$candidate/.config"
"$kernel/scripts/config" --file "$candidate/.config" -e SUSPEND -e PM_WAKELOCKS -d PM_AUTOSLEEP -d PM_USERSPACE_AUTOSLEEP -d HIBERNATION
"${kbuild[@]}" O="$candidate" olddefconfig
for variant in wakelock-control wakelock; do
    "${kbuild[@]}" O="$ack/out/m62-$variant" Image
    cmp "$ack/out/m62-$variant/usr/initramfs_data.cpio" "$ack/out/m62-sync/usr/initramfs_data.cpio"
    tools/m22_pack.sh "$ack/out/m62-$variant/arch/arm64/boot/Image" "src/m62/boot-$variant.img"
done
```

## Live procedure

Use the established test runner with the office IP and 240-second timed
dump. Verify USB root SSH and the runtime power-service masks on both boots.
Run Binder, ashmem and sync regression probes using a private executable
tmpfs. The control must lack the native wakelock sysfs files. The candidate
runs [wakelock_smoke.sh](../tools/m62/wakelock_smoke.sh) to acquire and release
a named lock, then verify that a five-second timed acquisition expires.
It checks both active and inactive sysfs lists and cleans up its own lock.
It reads `/sys/power/state` without requesting a sleep state.

After each timed dump, restore stock DTB/DTBO and baseline BOOT, verify the
live hashes with pre-flight, and save baseline init's `/run/e2fsck.out`.
