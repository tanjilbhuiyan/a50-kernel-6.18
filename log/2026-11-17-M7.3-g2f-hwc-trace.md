# M7.3 G2f investigation: HWC2 mode metadata

Scope: trace HWC2 display-mode initialization against the working baseline.
No kernel changes, builds, flashes or compositor restarts in this session.
All live commands ran as phablet. No root phone operations were needed.

## Result

The first mandatory query is Samsung's **EXYNOS_DISP_INFO (0x40f84704,
248 bytes)**. Both 64-bit and 32-bit vendor implementations return early
from getDisplayHWInfo when it fails, before FBIOGET_VSCREENINFO. G2e's
display ioctl switch has no such case and returns -ENOTTY. This identifies
a concrete ABI blocker behind the 0x0 initialization path. A fix has not
been boot-tested; visible rendering and M7.3 acceptance remain unverified.

The live baseline query succeeds, supplying version 2, PSR mode 2, chip
9610, mres disabled/count 1 with first entry (68,147,0,0,0). The stock
handler preserves caller version and reserved bytes. FBIOGET_VSCREENINFO
returns 1080x2340, physical 68x147 mm and reserved [1080,2340,0,0]. Three
optional mode-query ioctls all return ENOTTY on the working baseline;
the library falls back to the framebuffer-derived config for those.
Zero pixclock remains a property of both stock and candidate, not an
established cause of the mode mismatch.
