# 2026-11-07 M3.5 UFS storage, read-only

## Part 1: write-safety audit of the 6.18 UFS stack (host only, BEFORE any UFS boot) - ticket SAFETY rule
Device: SCSI "SAMSUNG KLUCG4J1ED-B0C1" rev 0003 (baseline /sys/block/sda/device/{vendor,model,rev}). UFS spec version
UNVERIFIED (4.14 exposes no descriptors); the guards below do not depend on it.

Every device-side write in drivers/ufs/core/ufshcd.c (6.18) and what happens with our planned configuration:
| call site | attribute/flag | condition | our case |

| __ufshcd_write_ee_control :6136 | wExceptionEventControl | exception setup | volatile control mask. KEEP |
| ufshcd_enable/disable_auto_bkops :6223/:6274 | fBackgroundOpsEn | probe (force reset), PM paths | 4.14 does the same; persistence UNVERIFIED -> SUPPRESS (safety switch) |

Other device-side traffic: UniPro/M-PHY peer attributes (e.g. ufs-exynos.c:1860 PA_TACTIVATE) are link-layer, re-negotiated
at every link startup (volatile). START STOP UNIT to the device W-LUN for power modes: volatile. SCSI sd probe/partition scan:
reads (MODE SENSE, READ). No filesystem is mounted.

FMP (inline crypto) in ufs-exynos: exynos_ufs_fmp_init issues SMC SMC_CMD_SMU/SMU_INIT to the secure world, but only if the
variant has EXYNOS_UFS_OPT_UFSPR_SECURE (ufs-exynos.c, gs101). A 9610 variant will not set it, AND we build with
CONFIG_SCSI_UFS_CRYPTO=n (stub, ufs-exynos.c:1428), so no SMC to the A50 secure world.

Power: the UFS VCC is a GPIO-switched fixed regulator marked regulator-boot-on in the stock DT; we do NOT describe it, so 6.18
never switches it (the bootloader's state stays).

### CORRECTION (2026-11-08) to the guards below
Layer 2(a) was wrong: set_disk_ro() does NOT make the block layer reject writes. block/blk-core.c bio_check_ro() only logs
"Trying to write to read-only block-device" and lets the bio through. Layer 2 was replaced by the allow-list guard in
"Part 3". The per-call-site skips in 2(b) are superseded too. The table's "KEEP" for wExceptionEventControl is also superseded
(its volatility was asserted, not verified): it is now blocked like every other write; only fDeviceInit passes.

### Planned guards (all three layers) [layer 2 superseded, see CORRECTION above]
1. DT: no "ref_clk" clock name, no "ref-clk-freq" property, no vcc/vccq regulators, no crypto.
2. Kernel safety switch (diag Kconfig, e.g. A50_UFS_SAFE): (a) sd: set_disk_ro() on every disk at revalidate, so the block layer
   rejects every write; (b) ufshcd: skip the bActiveICCLevel, fBackgroundOpsEn, WriteBooster, RTT, RTC/timestamp and bRefClkFreq
   writes (log "A50_UFS_SAFE: skipped <x>"). fDeviceInit and the exception mask stay (needed for init, volatile).
3. Initramfs: `blockdev --setro` on every sd* as its first action; never mount; reads only (BOOT hash check).

## Part 3 (2026-11-08): the write guard (kernel a50-ufs, reference/m35-ufs/0001-*.patch; CONFIG_A50_UFS_SAFE)
Default deny, at the points every command must pass (drivers/ufs/core/ufshcd.c):
- ufshcd_queuecommand: only TEST_UNIT_READY, REQUEST_SENSE, READ_6/10/16, INQUIRY, MODE_SENSE(6/10), START_STOP (power state),
  READ_CAPACITY(10/16), REPORT_LUNS. Anything else (all WRITE_*, UNMAP, FORMAT, SYNCHRONIZE_CACHE, WRITE_BUFFER, SECURITY_PROTOCOL_*,
  and SG_IO passthrough of those) is answered CHECK CONDITION / ILLEGAL REQUEST (asc 0x20, no retries), logged ratelimited, never sent.
- ufshcd_query_flag, _attr, _attr_qword, __ufshcd_query_descriptor: only READ_DESC/ATTR/FLAG and SET_FLAG fDeviceInit pass;
  every other opcode is logged and reports success without being sent.
- ufshcd_exec_raw_upiu_cmd, ufshcd_advanced_rpmb_req_handler: -EPERM.
Static DME attribute sets: not used by ufshcd.c or ufs-exynos.c (only defined in include/ufs/ufshcd.h).
tools/m22_build.sh refuses a kernel with SCSI_UFSHCD=y unless A50_UFS_SAFE=y and SCSI_UFS_CRYPTO/BSG are off (exit 3).
Host checks: without the guard: "REFUSED: UFS enabled without CONFIG_A50_UFS_SAFE=y", rc 3, no Image. With it: rc 0;
ufshcd_queuecommand calls scsi_build_sense/scsi_done; both guard strings in ufshcd.o. PHY_SAMSUNG_UFS not yet enabled (port).
NOT yet proven on hardware. Planned live negative test: `sync`/flush (SYNCHRONIZE_CACHE, harmless even if it got through) must log
"A50_UFS_SAFE: blocked SCSI opcode 0x35".

## Part 4 (2026-11-08): the port (branch a50-ufs on a50-pinctrl; patches reference/m35-ufs/). Host-only: built, NOT booted.
- PHY: drivers/phy/samsung/phy-exynos9610-ufs.c. PMA tables from ufs-cal-9610.c (byte offset / 4; lane stride 0x140 B = 0x50 words).
  Script cross-check against the CAL source: init_cfg PMA 11/11 entries identical in order; calib_of_hs_rate_a == _b; HS-G3 6/6 identical.
  wait_for_cal = 200 us (CAL COMMON_WAIT); wait_for_cdr = ufs_cal_wait_cdr_afc_check (0x1fc & 0x40, retoggle 0xf0).
  PMU isolation 0x724 mask 1 (4.14 default, no DT override in the stock DT).
- Host: ufs-exynos.c "samsung,exynos9610-ufs", template FSD (same PCS sequence and post_link as the CAL). Differences from FSD taken from
  the CAL: RX selector 4+lane (no BROKEN_RX_SEL_IDX), RX 0x84=1, TX 0x04=1, TX 0x8F=0x3E, no 0x201, truncated clock period (6 not 7),
  no PA_TX/RXTERMINATION writes. avail_ln_rx/tx read in pre_link (mainline reads them only later in phy_init, so FSD's loops would be empty).
  post_hce_enable: HCI_UFS_ACG_DISABLE (0xfc) set + HCI_IOP_ACG_DISABLE cleared (4.14, hw_rev 5). IOCC mask 0x300 at sysreg 0x13410000+0x1010.
  Power: FAST, up to HS-G3, 1 lane, series B (4.14 ufs,pmd-attr-* and PA_HS_MODE_B). The CAL's __BRD_SMDK entry 0x12C=0x10 APPLIES: the board
  filter is skipped when brd-for-cal=0 (stock DT).
- DT (b1ccc80da): pmu "samsung,exynos9610-pmu","syscon" (no exynos7-pmu fallback, that would bind the exynos-pmu driver with foreign data), sysreg_fsys, ufs, ufs_phy.
  dtc W=1 clean, 11,352 B, 4aa8b2d9...; dt-validate clean; negative (bogus clock-name) flagged by samsung,exynos-ufs.yaml.
  Safety re-checked in the compiled DTB: UFS host clock-names = core_clk, sclk_unipro_main; no ref-clk-freq; no *-supply.
- Build: rc 0 (out/m35-build, Image f911f40e..., 7,647,240 B) with A50_UFS_SAFE=y, crypto/BSG off, CONFIG_PM off.

### Known deviations from Samsung's sequence (UNVERIFIED on hardware; all link-layer or host-side)
1. PA_TXTRAILINGCLOCKS = 0x10: mainline's exynos_ufs_config_unipro always writes it; the CAL never does.
2. Mainline's generic post_link writes fixed PA_GRANULARITY/PA_TACTIVATE/PA_HIBERN8TIME before the CAL-equivalent adjustments (as for FSD).
3. DL timers 0x2041-3 are written after the variant callback, the CAL writes them first.
4. Not ported: CAL PWM calibration tables (HS only); hibern8 tables post_h8_enter/pre_h8_exit (no mainline hook). Safe only while CONFIG_PM=n and
   no clock gating caps: REQUIRED before enabling either.
5. SMU untouched: no SMC, no UFSP writes (UFSPR_SECURE + CONFIG_SCSI_UFS_CRYPTO=n). 4.14 calls SMC SMU_INIT (CONFIG_SCSI_UFS_EXYNOS_SMU=y).
   If the bootloader's SMU state does not allow non-secure access, expect read errors (safe failure).
6. No pinctrl on the UFS node: relies on the bootloader's pin state (reset, refclk-out).
