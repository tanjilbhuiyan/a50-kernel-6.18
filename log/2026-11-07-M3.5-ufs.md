Other device-side traffic: UniPro/M-PHY peer attributes (e.g. ufs-exynos.c:1860 PA_TACTIVATE) are link-layer, re-negotiated
at every link startup (volatile). START STOP UNIT to the device W-LUN for power modes: volatile. SCSI sd probe/partition scan:
reads (MODE SENSE, READ). No filesystem is mounted.

FMP (inline crypto) in ufs-exynos: exynos_ufs_fmp_init issues SMC SMC_CMD_SMU/SMU_INIT to the secure world, but only if the
variant has EXYNOS_UFS_OPT_UFSPR_SECURE (ufs-exynos.c, gs101). A 9610 variant will not set it, AND we build with
CONFIG_SCSI_UFS_CRYPTO=n (stub, ufs-exynos.c:1428), so no SMC to the A50 secure world.

Power: the UFS VCC is a GPIO-switched fixed regulator marked regulator-boot-on in the stock DT; we do NOT describe it, so 6.18
never switches it (the bootloader's state stays).

### CORRECTION (2026-11-08) to the guards below
Layer 2(a) was wrong: set_disk_ro() does NOT make the block layer reject writes. block/blk-core.c bio_check_ro() only logs
"Trying to write to read-only block-device" and lets the bio through. Layer 2 was replaced by the allow-list guard in
"Part 3". The per-call-site skips in 2(b) are superseded too. The table's "KEEP" for wExceptionEventControl is also superseded
(its volatility was asserted, not verified): it is now blocked like every other write; only fDeviceInit passes.

### Planned guards (all three layers) [layer 2 superseded, see CORRECTION above]
1. DT: no "ref_clk" clock name, no "ref-clk-freq" property, no vcc/vccq regulators, no crypto.
2. Kernel safety switch (diag Kconfig, e.g. A50_UFS_SAFE): (a) sd: set_disk_ro() on every disk at revalidate, so the block layer
   rejects every write; (b) ufshcd: skip the bActiveICCLevel, fBackgroundOpsEn, WriteBooster, RTT, RTC/timestamp and bRefClkFreq
   writes (log "A50_UFS_SAFE: skipped <x>"). fDeviceInit and the exception mask stay (needed for init, volatile).
3. Initramfs: `blockdev --setro` on every sd* as its first action; never mount; reads only (BOOT hash check).

## Part 3 (2026-11-08): the write guard (kernel a50-ufs, reference/m35-ufs/0001-*.patch; CONFIG_A50_UFS_SAFE)
Default deny, at the points every command must pass (drivers/ufs/core/ufshcd.c):
- ufshcd_queuecommand: only TEST_UNIT_READY, REQUEST_SENSE, READ_6/10/16, INQUIRY, MODE_SENSE(6/10), START_STOP (power state),
  READ_CAPACITY(10/16), REPORT_LUNS. Anything else (all WRITE_*, UNMAP, FORMAT, SYNCHRONIZE_CACHE, WRITE_BUFFER, SECURITY_PROTOCOL_*,

### Known deviations from Samsung's sequence (UNVERIFIED on hardware; all link-layer or host-side)
1. PA_TXTRAILINGCLOCKS = 0x10: mainline's exynos_ufs_config_unipro always writes it; the CAL never does.
2. Mainline's generic post_link writes fixed PA_GRANULARITY/PA_TACTIVATE/PA_HIBERN8TIME before the CAL-equivalent adjustments (as for FSD).
3. DL timers 0x2041-3 are written after the variant callback, the CAL writes them first.
4. Not ported: CAL PWM calibration tables (HS only); hibern8 tables post_h8_enter/pre_h8_exit (no mainline hook). Safe only while CONFIG_PM=n and
   no clock gating caps: REQUIRED before enabling either.
5. SMU untouched: no SMC, no UFSP writes (UFSPR_SECURE + CONFIG_SCSI_UFS_CRYPTO=n). 4.14 calls SMC SMU_INIT (CONFIG_SCSI_UFS_EXYNOS_SMU=y).
   If the bootloader's SMU state does not allow non-secure access, expect read errors (safe failure).
6. No pinctrl on the UFS node: relies on the bootloader's pin state (reset, refclk-out).
