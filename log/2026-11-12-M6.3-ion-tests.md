# 2026-11-12 M6.3 ION native and compat tests

The [ABI design](2026-11-12-M6.3-ion-design.md) records the baseline heap
table and captured allocation payloads. First test source is
`a50-m63-ion-test/33c851162603f15d9d01baa4b7fba27cf19b7126`.
The source adds the ION frontend and legacy tracking counters while keeping
UFS/SCSI unchanged. [Source patch](../reference/m63-ion/0001-ion-native-system-frontend.patch).

## Build

The native config starts from the passing M6.2 wakelock `.config` and
enables `ION_EXYNOS_COMPAT`, selecting native DMA heaps and the system heap.
The compat candidate starts from that native config and enables `COMPAT`.
Use the pinned build variables and `kbuild` command from the
[ashmem recipe](2026-11-11-M6.2-ashmem.md) with output paths
`src/ack-6.18/out/m63-ion` and `src/ack-6.18/out/m63-ion-compat`.
Each retains the same embedded initramfs, diagnostic masks and timed dump.
[Native config delta](../reference/m63-ion/config-delta.txt) ·
[Input hashes](../reference/m63-ion/inputs.json).

Native BOOT is `src/m63/boot-ion.img`, SHA256
`f36874fa751801b4227fadc5c355c71068080841a297f2b6f2424acfbbdb19e6`.
The frontend advertises only the implemented heap 0 with native immediate
free semantics. Six reserved/secure heaps remain unsupported and are not
reported as working heaps. The baseline table has seven entries. The tested
query ABI is the supported heap's name, ID and type, plus count/bounds/error
handling. This is an explicit implementation subset.

The replay helper is [ion_smoke.c](../tools/m63/ion_smoke.c). Its generated
`replay.h` contains every successful allocation from
`reference/m63-ion/baseline-allocator.jsonl`, in order. `replay.json` records
the same 32 length/mask/flag tuples in a portable format. Compile with NDK
r27, the donor `ion.h`, target `linux/dma-buf.h`, and the generated header,
using `-std=gnu11 -static -O2 -Wall -Wextra -Werror`. The AArch64 compiler is
`aarch64-linux-android30-clang`, the AArch32 compiler is
`armv7a-linux-androideabi30-clang`. Both helpers assert the 24/24/52-byte
layouts and the actual ioctl numbers.

`tools/m63/build_smoke.sh` regenerates the replay header from tracked JSON
and obtains the pinned UAPI headers with `git show`, without switching the
shared checkout. A fresh rebuild produced the exact tested SHA256 hashes:
`650df95c2b5bf96a6595a8184fb9104ecf0e122807dc63a9643008f226f41053`
(AArch64) and
`5eea7732c7035a4e6504ba6a5d51d034075f74f215ef36c64fbc5786cca6ed7e`
(AArch32). Run it with a fresh output directory; `A50_NDK_BIN` can select
the same NDK compiler installation on another host.

## Native live result

Baseline pre-flight passed. The native image flashed at 18:49:18. USB root
SSH reached 6.18 and the replay passed all 32 measured allocation requests.
Each checked sampled zero initialization, shared mappings, DMA_BUF_SYNC and
balanced TRACK/UNTRACK. Query validation and allocation boundary tests passed.
Eight copyout-failure allocations left the process's fd count unchanged.
The dup/close, fork and exec tests passed with independent tracking state.
Binder, ashmem and software-fence probes also passed. [Live probes](../reference/m63-ion/native-smoke.txt).

A read of debugfs after the helper completed reported **0 DMA-BUF objects
and 0 bytes**, with MemAvailable 3,426,144 KiB. This verifies that the replay
and copyout tests left no exported buffers behind. [Post-test buffers](../reference/m63-ion/native-after-buffers.txt).

The timed dump returned to Download mode at 18:53:55. Stock DTB, DTBO and
baseline BOOT restored at 18:54:12; baseline boot time was 18:54:27. Post-flight
verified all three partition hashes. Baseline init's saved fsck reported
clean, 6323/3440640 files and 1982827/13745152 blocks, with no repairs.
[Runner and post-flight](../reference/m63-ion/native-run.txt) ·
[Saved baseline fsck](../reference/m63-ion/native-baseline-fsck.txt).

## Compat live result

Compat BOOT `src/m63/boot-ion-compat.img`, SHA256
`0ac3f6d4cc38f3b69caba71fb94982b21bf67b166baae0fcd167bcb88f946b9d`,
flashed at 19:08:02. Its only intentional change was enabling AArch32
compatibility; the resolved defaults are recorded in
[the config delta](../reference/m63-ion/compat-config-delta.txt).
Both AArch64 and AArch32 helpers passed the same 32 captured requests and
all query, bounds, copyout and tracking/lifetime tests. Debugfs again
reported zero exported objects and bytes after both helpers completed.
[Live probes](../reference/m63-ion/compat-smoke.txt).

The phone returned to Download at 19:12:40 and stock restored at 19:12:57.
Baseline boot time was 19:13:12, battery 100% Charging, with all three
partition hashes verified. Saved baseline fsck was clean, 6312/3440640
files and 1984102/13745152 blocks, with no repairs.
[Runner and post-flight](../reference/m63-ion/compat-run.txt) ·
[Saved baseline fsck](../reference/m63-ion/compat-baseline-fsck.txt).

Both dumps retain the userdata guard self-test and exact allowed range,
one unsupported UNMAP refusal, and userdata read-write at all observer
snapshots. There was no journal abort, WRITE(6) fallback, DMA-BUF accounting
warning or new failed unit. Android remained STOPPED with partition startup
masked, as intended for isolated ABI tests. Actual allocator-service startup
belongs to M6.4; hardware DMA through these buffers remains unverified.
[Native dump](../reference/m63-ion/native-dump.txt) ·
[Compat dump](../reference/m63-ion/compat-dump.txt).
