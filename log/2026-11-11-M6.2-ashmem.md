# 2026-11-11 M6.2 native ACK Rust ashmem

The comparison is the passing [BinderFS candidate](2026-11-11-M6.2-binderfs.md)
at `e8a5a7fea`. This test adds the built-in native ashmem driver and its Rust
and staging prerequisites. It retains the M5.4 initramfs, built-in Android
partition-unit mask, USB SSH, userdata guard, DT and timed dump.

## Build and smoke helper

The first build reached `rust/kernel.o` and failed with E0560. The generated
Rust bindings lack three block operations fields because the C headers only
declare those reservations with `CONFIG_ANDROID_KABI_RESERVE=y`. Commit
`f1a66edfab03eebbc7db29f969a9883db7034cde` makes the three
Rust initializers conditional on that same symbol. The passing Binder
config keeps KABI reservations disabled, so this leaves the C block layouts
and UFS/SCSI source untouched. [Compiler evidence](../reference/m62-ashmem/kabi-build-error.txt) ·
[Kernel patch](../reference/m62-ashmem/0001-guard-rust-block-kabi-initializers.patch).

The next build compiled ashmem and failed at link. The Rust `dma_buf` module
referenced C functions excluded by `CONFIG_DMA_SHARED_BUFFER`. Final test
commit `a50-m62-ashmem-test/078d5dbf171838e43dee64ecd409309113862e8f`
gates the Rust module on the same symbol. DMA-BUF and sync stay disabled for
this test. [Linker evidence](../reference/m62-ashmem/dmabuf-link-error.txt) ·
[Kernel patch](../reference/m62-ashmem/0002-gate-rust-dmabuf.patch).

The final BOOT image is `src/m62/boot-ashmem.img`, 29,341,696 bytes, SHA256
`287f3ca0c02078a8891f9d24f462878ba1196105c7438d05873d867f1fe3b20a`.
The embedded cpio matched the Binder image byte for byte. [Config delta](../reference/m62-ashmem/config-delta.txt) ·
[Input hashes](../reference/m62-ashmem/inputs.json).

Build from the outer repo with the kernel on the pinned ashmem test commit.
The config comes directly from the passing Binder build. Pass `RUSTC` and
`BINDGEN` as make assignments so Kbuild uses the pinned versions.

```bash

export LIBCLANG_PATH="$clang_dir/lib"

```

The native AArch64 smoke helper opens the `/dev/ashmem` character device,
sets and reads the region size using ACK's ioctl definitions, and checks that
a second shared mapping sees a write through the first. The Binder helper
from the previous test checks regression on the same boot.

```sh
ndk=src/ack-6.18/prebuilts/ndk-r27/toolchains/llvm/prebuilt/linux-x86_64/bin

    -I src/m62/ashmem-include tools/m62/ashmem_smoke.c -o src/m62/ashmem-smoke
```

## Live procedure

With the owner present, verify the baseline pre-flight and the approved
flash method. Use the existing M5.4 USB watcher and 240-second dump.
Stage the ashmem and Binder helpers under `/run`, then execute them from a
private executable tmpfs as in the Binder candidate. Require the masked
partition unit, Android `STOPPED`, rw userdata, Binder protocol 8 on all
three contexts and a passing ashmem check. Archive the timed dump, stock
rollback pre-flight and saved baseline init fsck. AArch32 compatibility,
sync and wakelocks are separate checks.

The owner confirmed presence, Claude Code idle, and the Heimdall
DTB/DTBO/BOOT exception for this ashmem boot and restore.
