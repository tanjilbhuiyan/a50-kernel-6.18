# 2026-11-10 M4.6 Thermal (TMU)

## Design facts
4.14 reads temperature through ACPM (exynos9610_tmu_read -> exynos_acpm_tmu_set_read_temp, drivers/thermal/samsung/exynos_acpm_tmu.c), channel 7 (stock acpm_tmu node), request type TMU_IPC_READ_TEMP 0x02 with tzid in byte 2; reply type, tzid, temp, stat in bytes 0-3 (exynos_acpm_tmu.h). Byte 2 overlaps the ACPM sequence number (bits 21:16), which mainline uses to match replies, so the reply layout is checked first. Zones: BIG id 0, LITTLE 1, G3D 2, ISP 3. Baseline temperatures: reference/m44-buses/baseline-thermal.txt.

a50-m46-test = a50-m36-clean + a50-pmic (no I2C nodes) + TEST ONLY tools/m46/a50-tmu-probe.c. Only READ_TEMP is sent. src/m46/boot-m46-probe.img dc22b284...; DT src/m46/dt.img.

## Probe run 1 (12:08-12:12): firmware silent on this boot
Runner exit 0, rollback OK. Dump: reference/m46-thermal/2026-11-10-probe-dump.txt. ch7 ap_poll=1 qlen=5, queues empty; "no reply in 20000 us" to READ_TEMP tz0. In the same boot the S2MPU09 driver's first read (LDO1, 0.19 s) timed out (-62), so its probe failed and USB waited for LDO14 (no gadget). The same PMIC reads worked in every M4.2/M4.3 run. Difference: the phone had been idle on the baseline since 01:54 (overnight). Rerunning the same image on a freshly rebooted phone.

## Probe run 2 (12:13-12:16): same result, so systematic
Fresh boot, same image: READ_TEMP tz0 at 0.07 s unanswered, then the S2MPU09 driver's first read at 0.20 s timed out (-62), USB waited for LDO14. M4.2/M4.3 images (no thermal request) read the PMIC fine at 0.08-0.2 s. Reading: an uninitialised READ_TEMP stalls the ACPM firmware for the rest of the boot (UNVERIFIED how; both phones recovered normally through Download mode). 4.14 always sends TMU_IPC_INIT (type 0x01) first.

## Probe 3 (built): TMU_IPC_INIT, then READ_TEMP tz 0-3; raw replies logged. src/m46/boot-m46-probe2.img.

## Probe 3 (12:19-12:23): INIT is not answered either
TMU_IPC_INIT on channel 7 got no reply; the PMIC driver then timed out as before (rc=0 rollback, pre-flight passed). Dump: reference/m46-thermal/2026-11-10-probe3-dump.txt. On the baseline the thermal channel is served by a firmware plugin that 4.14 sets up at boot ("plugin(id = 4) attach done", /proc/first_kmsg); under 6.18 that does not happen, so channel 7 is not served and a request on it stalls ACPM IPC for the boot.
Decision: thermal through ACPM is not pursued. Next: read the TMU hardware registers directly (read-only), as 4.14's non-ACPM path does. Note for M4.7: the baseline's CPU DVFS also depends on a firmware plugin (id 2), so M4.7 may be blocked the same way.
4.14 has no register-based temperature read for 9610 (exynos9610_tmu_read returns 0 without ACPM thermal). Read-only register probe (tools/m46/a50-tmu-regs.c, branch a50-m46-test2 = a50-m36-clean + a50-pmic): no firmware messages.

## TMU register probe result (12:28-12:32): sensors run without the firmware's thermal handling
Runner exit 0, pre-flight passed; dump reference/m46-thermal/2026-11-10-regs-dump.txt. No firmware messages, and this time the S2MPU09 driver and USB worked (confirms the earlier failures came from the channel-7 requests).
CONTROL 0x9403 (bit 0 = core enable on), registers stable over three passes one second apart. TRIMINFO0-2 non-zero, TRIMINFO3 zero: three sensors.
Decode (UNVERIFIED field layout: 9-bit codes per 4.14 EXYNOS_TMU_TEMP_MASK 0x1ff, two-point trimming per TRIMINFO bit 23 CALIB_SEL, trim points 25/85 C from the stock DT): CURRENT_TEMP1_0 0x00023f20 gives codes 0x120 (s0) and 0x11f (s1); CURRENT_TEMP4_2 0x121 (s2). TRIMINFO e1/e2: s0 278/338, s1 278/338, s2 279/338. Temperatures about 35, 34, 35 C at an idle early boot (baseline under UT load read 60-73 C). Zone map from the stock DT sensors masks: G3D = s0, LITTLE and ISP = s1, BIG = s2.
