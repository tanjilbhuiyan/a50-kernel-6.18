## I3 results

**The concrete lead is GStreamer codec discovery.** The GUI/display-plugin
hypothesis is unsupported by this run: the original handler's startup environment
matches the stock control, neither early map contains a QPA plugin or libmirclient,
and the bounded debug child produces zero Qt/Mir/Wayland log bytes before timeout.
That absence alone does not prove which instruction blocks; the following
read-only supplemental inspection identifies a subprocess wait.

- Original handler PID 2823 has one thread. Its ppoll array is fd 5 (events
  0x39), fd 8 (0x38) and fd 9 (0x39). Fd 5/6 are unnamed socketpair endpoints
  with creation-time peer credentials referring to the handler; fd 8/9 are
  pipes. Do not interpret socketpair SO_PEERCRED as proof that a peer is still
  executing in the original process after a fork.
- Both service names are unowned before the manual launch. Diagnostic PID 4465
  runs with the original display/bus environment and debug logging, then is
  terminated/reaped at 25.022 s (SIGTERM, zero log bytes). No original-service
  restart or readiness fabrication. Host timeout cleanup was tested beforehand.
- The first supplemental check at uptime 160.09 finds restarted handler PID
  7997, but `/proc/PID/task/PID/children` is unavailable with this config; its
  absence is not evidence of no children. The follow-up enumerates PPid instead.
- At uptime **295.11**, handler **11330** is in ppoll and has direct child
  **11333**, `gst-plugin-scanner`, with six threads. The scanner main thread
  waits in a futex. Bounded stack inspection saves executable return-site
  candidates only, with no raw stack contents and no ptrace pause.
- Scanner candidates run through libhybris/libhidlbase, Android's
  `IOmxStore::getServiceInternal`, `OmxInfoBuilder::buildMediaCodecList`,
  `MediaCodecList`, `media_codec_list_count_codecs` and `libgsthybris.so`.
  Installed-library symbol checks map file offsets through ELF PT_LOAD first.
  In the plugin, candidate **0x92d8** is immediately after the **0x92d4** call
  to `media_codec_list_count_codecs`. This supports the codec-probe interpretation;
  stack words remain candidates rather than a formally unwound backtrace.
- Independent Android state shows `vendor.media.omx=[restarting]` and repeated
  inability to start `android.hardware.media.omx@1.0::IOmxStore/default`.
  This is a hardware-codec dependency, distinct from the now-working PulseAudio
  deferral. No claim yet that excluding the plugin repairs normal startup.
