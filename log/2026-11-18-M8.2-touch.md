# 2026-11-18 M8.2 Melfas MSS100 touchscreen

Session by Claude Code. Owner: "yes" (start M8.2).

## Stock facts (reference/stock-dt/dtbo.3.dts ~2196-2240 and __fixups__; 4.14 driver source)
- `mms_ts@48` on `i2c@13870000`, compatible `melfas,mms_ts`, firmware `tsp_melfas/mss100_a50.fw`.
- Supply `tsp_ldo_en`: `regulator-fixed`, 3.0 V, GPIO **gpg3-1** active high (fixup `gpg3 ... tsp_ldo_en:gpio:0`).
- Interrupt **gpa0-0** (`melfas,irq-gpio`, fixup `gpa0 ... mms_ts@48:melfas,irq-gpio:0`); stock driver requests
  `IRQF_TRIGGER_LOW | IRQF_ONESHOT` (`melfas_mss100.c:1606`). Pin states: `on_state` gpa0-0 function 0xf (EINT), no
  pull; `off_state` input, pull-down.
- `melfas,event_info = <0x08 0x0c>`: event format 8, 12-byte events. 4.14 `melfas_mss100.h:147`
  `EVENT_FORMAT_WITH_PRESSURE_2BYTE 8`; layout in `mms_input_event_handler()` (`melfas_mss100.h:680`): format 3 with a
  2-byte Z in bytes 5-6.

## Driver choice
The MSS100 register map is MIP4 (4.14 `melfas_mss100_reg.h` R0/R1 offsets equal mainline `melfas_mip4.c` MIP4_R0/R1).
Mainline reads the event format from the chip and supports formats 0, 1, 3. Chosen: mainline `melfas_mip4` plus a
format-8 patch (modern 6.18 driver, small change) instead of porting Samsung's MSS100 driver. Mainline never writes
firmware by itself; its only firmware path is the root-only sysfs `update_fw`, which no test touches. Power: mainline
handles one `ce-gpios` line with a 200-300 ms boot delay; the LDO enable gpg3-1 is used as that chip enable.
Host check `tools/m82/mip4_format_test.py`: decodes packets built from Samsung's layout for formats 3 and 8 (6/6
correct); two broken variants caught.

7066/3440640 files. The run ended early through a softlockup panic at 368 s (see below), which the diagnostics dumped.
- **The controller answers once its supply is on:** `3-0048` bound to `mip4_ts`; sysfs `product_id=1004`,
  `fw_version=EEEE 0301 1130 2F02`, `hw_version=2019-A50`, `ic_name` empty. `/dev/input/event0` "MELFAS MIP4
  Touchscreen" (13c5:1004), ABS MT X/Y 0..4095, 10 slots. gpg3-1 `ce` output high; gpa0-0 muxed to touch-irq-pins.
- **Interrupt storm without data:** `Empty packet` from 36.68 s at sub-millisecond intervals; `mip4_ts` IRQ (gpa0 0,
  level) 18,288 at ~40 s, 185,331 at 80 s, 401,932 at 140 s (~3,600/s); bus-4 IRQ 91,511 at ~40 s.
- **No touch events:** 60 s passive capture during the owner's touching: 0 contacts, 0 X/Y events.
- **Soft lockup:** late in the run the packets became `Unknown key: 1` (3,189 lines in the 128 KB dump buffer) until
  `watchdog: BUG: soft lockup - CPU#5 stuck for 22s! [irq/70-mip4_ts:97]` and `Kernel panic - not syncing: softlockup`
  at 368 s.
- Session until then: Lomiri active, `NRestarts=0`; systemd `running`, 0 failed units.

Interpretation (unverified): the MSS100 may not implement MIP4's EVENT_SUPPORTED_FUNC/format registers (Samsung's
driver never reads them; it takes format 8 / size 12 from the DT). Event size 0 would make mainline's decode loop
`for (i = 0; i < size; i += ts->event_size)` never advance (the soft lockup), and format 0 would decode packets as keys.
The empty-packet storm is unexplained: either the chip holds INT low, or the wake-up EINT trigger polarity is wrong
(an idle-high line with a level-high trigger would storm at idle and go quiet during a touch, consistent with zero
events). Samsung requests `IRQF_TRIGGER_LOW` and treats an empty packet as an error (`melfas_mss100.c:970`).

## M8.2 acceptance (P3r)
1. Driver choice justified from protocol evidence; firmware-write paths disabled: **met** (mainline MIP4 + format 8 +
   DT event-format fallback; no automatic firmware path; `update_fw` never touched).
2. Multitouch coordinates matching the panel orientation: **met** (owner operated Lomiri by touch; full-range
   coordinates, two slots).
3. Power on/off follows the panel blank state without errors; suspend untested: **open**. The driver powers the chip at
   probe; panel blank/unblank does not change it yet, and the start-up storm (empty packets with INT low until the first
   touch, also seen on stock) costs interrupts until then.
4. Clean stack and export: patches below; stock restore/fsck clean.
