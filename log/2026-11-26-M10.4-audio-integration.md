# 2026-11-26 M10.4 audio integration

Ticket: `tasks/M10.4-audio-integration.md`. Depends on M10.3, closed 2026-11-26
(`log/2026-11-22-M10.3-tfa9872.md`).

## Starting point
- Kernel audio stack on WIP `a50-m10-b2-wip` `5f22a49c5`:
  - ABOX, RT5665, TFA9872 with the factory calibration gate, high-res
    timers, tfadsp.bin.
  - Last phone-tested images: B2b5 (speaker audible) / B2m.
- ADR-0005 still applies on every 6.18 boot: a per-boot read-only overlay
  of `/etc/pulse/touch.pa` without `module-droid-discover`, so PulseAudio
  has a null sink. The M5 `a50-audio-route` mask is also still active.
- M10.4 removes both and runs PulseAudio on `module-droid-discover`, which
  talks to the Android audio HAL over hwbinder.
- On 6.18, `vendor.audio-hal` crash-loops: `received signal 11` every
  ~5 s in the B2b/B2b5 kernel logs, also in M7.5. No backtrace was ever
  captured. M7.5 showed PulseAudio blocking in startup while the HAL is
  down.
- What the HAL needs (M10.1 contract): the 32-bit
  `audio.primary.exynos9610.so`, standard ALSA PCM/CTL ioctls,
  `controlC0` held while idle. Stock `/dev/snd` has `comprC0D5`
  (compress offload) and hwdep `hwC0D3`, `hwC0D9` besides the PCMs.
  Earlier 6.18 comparisons covered PCMs and controls only. Four
  HAL-relevant control names are absent on 6.18: BT SCO MIC/SPK Enable,
  `Debug Buffer Switch`, `Disable NG2`.

## C1 prep (host only)
- Read-only capture on the unchanged B2b5 images (copied as m104c1, same
  hashes).
- `tools/m10/collect_m104c1.sh` reads at ~150 s:
  - `/dev/snd`, `/proc/asound/{devices,pcm}`;
  - in the container: HAL init state and pids, its rc, its `/dev/snd`
    view, `logcat -b crash`, the newest tombstone (first 160 lines), and
    audio-related main/system logcat;
  - kernel lines for the HAL and audio.
- No mixer, PulseAudio or HAL change.
- `tools/m10/run_m104c1.sh` (standard cycle, calibration check, stock
  restore), `reference/m10-audio/m104c1-inputs.json`, 32 hashes.
- Goal: the HAL's backtrace, to decide the one fix for the next boot.

## 2026-11-29 C1 result (owner present; home network, stock at 192.168.0.171)

- Unchanged B2b5 images. Pre-flight passed, fsck clean (7218 files).
  Calibration matched before and after; 0 occurrences published.
- ALSA nodes on 6.18: `comprC0D5` (compress, device 5), `controlC0`,
  PCMs 0-4/6/7 playback and 8-12 capture, `timer`. Same in the container
  (`system:audio 0660`).
- Stock also has hwdep `hwC0D3`/`hwC0D9` and card 1 `abox_dump`; 6.18
  lacks those (the M10.2 port left `abox_dump` out).
- `init.svc.vendor.audio-hal=restarting`. The rc file is
  `/vendor/bin/hw/android.hardware.audio.service`, user audioserver.
  Init also logs `createProcessGroup(1041, ...) failed: Read-only file
  system` (the cgroup v1 `/acct` path), the same as for every service.
- **Not audio-specific.** `logcat -b crash` has 147 `Fatal signal 11
  (SIGSEGV), code 1 (SEGV_MAPERR)` lines, all in the main thread (tid ==
  pid):
  - 98 `android.hardwar`, 25 `vendor.samsung.`, 24 `camera_service`.
  - Fault addresses 0xff05..-0xff7d.. (top of a 32-bit address space).
  - The kernel shows six services restarting every ~5 s with `received
    signal 11`: vendor.audio-hal, vendor.cas-hal-1-2,
    vendor.drm-widevine-hal-1-3, vendor.media.omx,
    sec-camera-provider-4-0, camera_service. Each dies ~0.5 s after start.
- No tombstone (`/data/tombstones` empty) and no `DEBUG` backtrace in
  logcat: the container's crash_dump/tombstoned path produces nothing.
- No earlier project record analysed this crash set. M7.5 saw only the
  audio-hal and media.omx restarts.

## C2 prep (host only)

- Same images (copied as m104c2).
- `tools/m10/collect_m104c2.sh` runs on stock first (via
  `run_m104c2.sh`, read-only) and then on 6.18:
  - every `init.svc.*` state;
  - each service's binary from the rc files and its ELF class (01 =
    32-bit, 02 = 64-bit).
- On 6.18 only it sets `debug.exception-trace=1` at 100 s (runtime
  sysctl, restored at the end). After bionic's handler fails to run
  crash_dump and resets to SIG_DFL, the re-fault is unhandled, so the
  arm64 kernel prints it: `arm64_show_signal`, `traps.c`, with ESR, the
  VMA (library + offset) and registers.
- It collects the first four reports per process name at 140 s.
- `m104c2-inputs.json`, 32 hashes.
