## Build and probe

Use the pinned Clang, Rust and bindgen settings in the ashmem build log.
Set `out=$ack/out/m62-sync` before defining its `kbuild` array. From the
outer repo, derive the config and pack the image as follows.

```bash
mkdir -p "$out"
cp "$ack/out/m62-ashmem/.config" "$out/.config"
"$kernel/scripts/config" --file "$out/.config" -e SYNC_FILE -e SW_SYNC
"${kbuild[@]}" olddefconfig
"$kernel/scripts/diffconfig" "$ack/out/m62-ashmem/.config" "$out/.config"
"${kbuild[@]}" Image
cmp "$out/usr/initramfs_data.cpio" "$ack/out/m62-ashmem/usr/initramfs_data.cpio"
tools/m22_pack.sh "$out/arch/arm64/boot/Image" src/m62/boot-sync.img
```

The AArch64 probe links the ACK sync selftest helpers from the tested tree.
It creates one fence per independent software timeline, merges them with
`SYNC_IOC_MERGE`, checks the constituent status through `SYNC_IOC_FILE_INFO`,
and verifies that polling reports ready only after both timelines advance.

```sh
kernel=src/ack-6.18/common
ndk=src/ack-6.18/prebuilts/ndk-r27/toolchains/llvm/prebuilt/linux-x86_64/bin
selftest=$kernel/tools/testing/selftests/sync
mkdir -p src/m62/sync-include/linux
git -C "$kernel" show 078d5dbf1:include/uapi/linux/sync_file.h > src/m62/sync-include/linux/sync_file.h
"$ndk/aarch64-linux-android30-clang" -std=gnu11 -static -O2 -Wall -Wextra -Werror \
    -I src/m62/sync-include -I "$selftest" tools/m62/sync_smoke.c "$selftest/sync.c" -o src/m62/sync-smoke
```

## Live procedure

Use the M5.4 USB watcher and the timed dump. Verify the Android partition
mask, Android `STOPPED`, rw userdata and the Binder and ashmem regressions
as in the previous test. Stage the three probes under `/run` and run them
from a private executable tmpfs. The software timeline endpoint is
`/sys/kernel/debug/sync/sw_sync` on the host. Use the existing debugfs mount
if present and remove any diagnostic mount after the probe. Save the timed
dump, post-flight and baseline init fsck after restoring stock.
