## Host continuation

An Image/vmlinux already existed after enabling Exynos tracing. The
resumed port includes the Samsung platform headers and fixed-clock CAL,
PM/QoS/BTS/thermal compatibility interfaces. The 4.14-to-6.18 changes cover
timers, shrinkers, VMA flags/locking/iteration, user pages, file references,
DMA reservation types, explicit sync files and platform removal callbacks.
The vendor per-core PM QoS wrappers were removed in favor of direct ARM
r26p0 scheduling/ioctl calls. DMA-fence implicit synchronization stays off,
as in the stock configuration; enabling that optional path is not supported
by this build. Native explicit sync support remains configured.

Continuation fixes:

- Without DVFS, Samsung's platform leaves the current/max frequency fields
  zero and its platform header advertises 5000 kHz. Populate the measured
  260000 kHz and report that value without an extra factor of 1000.
- PMU reads access only the real G3D status register, with validated offset,
  pointer and mapping failure handling. Refuse probe if the measured domain
  is unavailable. No PMU write is implemented.
- Unsupported secure calls, power controls and frequency changes return
  errors. Build-time checks require no DVFS/runtime domain PM and protected
  rendering unsupported. No secure-world transition is fabricated.
- Native MIN/MAX definitions replace conflicting private macro definitions.
- The VMA iterator port now respects `vm_start_gap()`/`vm_end_gap()`, including
  a stack whose VMA lies above the allocation's high limit. Host tests extract
  the actual search functions, exercise guard/limit/alignment/shader/4 GB/
  overflow cases, and reject three deliberately broken implementations.

The new G1 DTS includes the tested D4a display setup and the stock GPU
register range/IRQ names. A fixed-clock provider describes G0b's measured
260 MHz without programming the PLL. No new regulator/domain control.

`mali_kbase.a50_g1_probe_only=1` is a diagnostic boot parameter. Only
VERSION_CHECK, SET_FLAGS and GET_GPUPROPS are allowed, preventing background
vendor clients allocating/submitting GPU work in G1. It defaults off in
source; removing it is a separate future boot. This is not a claim that the
memory, import, job or rendering paths work.

## Remaining M7.3 work

G1 establishes driver initialization and metadata ABI only. Actual buffer
allocation/import/cache maintenance, mapped GPU memory, explicit fences,
GPU jobs, off-screen rendering and eventual Lomiri remain unvalidated.
The next boot must deliberately remove the metadata-only restriction and
exercise those paths with meaningful outputs. Secure heaps/rendering,
DVFS, regulator/power cycling and suspend remain unsupported here.
M7.3 stays in progress. Do not infer M7 completion from a `/dev/mali0` node.
