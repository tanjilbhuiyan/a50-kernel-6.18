## The driver and DT (both boots)

- **Kernel:** branch `a50-m72-d2a-test`, commit `a8319f32d`, on the M6.4 test-7 source `bd3fe49b2`, without the D0–D1 probe
  ([patch](../reference/m72-display/0005-TEST-ONLY-minimal-fbdev-driver-on-the-handed-over-A5.patch)).
- **`drivers/video/fbdev/a50-decon.c`** keeps the command-mode state S-Boot leaves (D0c) and provides:
  - an fbdev device on the reserved boot framebuffer (a8r8g8b8 1080x2340, as found in D1);
  - one frame per `FBIOPAN_DISPLAY`, using D1's trigger sequence, masked again on DECON frame-done or after 100 ms;
  - TE timestamps (rising edge on `gpc2-3`) in the platform device's `vsync` attribute, notified while
    `S3CFB_SET_VSYNC_INT` is on;
  - `S3CFB_POWER_MODE` and `FBIOBLANK` accepted as no-ops.

  `S3CFB_WIN_CONFIG` is not implemented yet.
- **`exynos9610-a50-d2.dts`:** the tested M6.3 SysMMU DT, with simplefb disabled and a root-level `decon_f@148b0000` node.
  It carries the stock DECON registers, SPI 199/200/203, `te-gpios = <&gpc2 3>`, the TOP/DISPAUD/DPU SysMMU clocks, and
  `memory-region` pointing at the reserved boot framebuffer. The node sits at the root so the device is
  `/sys/devices/platform/148b0000.decon_f`, the path the stock composer reads. Decompiling shows the D2 DTB differs from
  the tested SysMMU DTB only by these additions; the M6.3 DT entry decompiles identically to a rebuild.
- **DT image:** `src/m72/dt-d2.img`, sha256 `28385671e2da775bcd95749eac6367a9a93857b7f336e0257d9552b3178f2710` (the repack after the node moved to the root; it matches both input manifests)
  (round-trip identical).
- **Config and initramfs** are byte-identical to M6.4 test 7. The guard and sense host tests pass.
- **Host test:** `tools/m72/fb_test.c`, a static NDK binary `src/m72/fb-test`. It reads the fbdev geometry, draws 8
  vertical colour bars over a brightness ramp, pans, counts `vsync` notifications for one second with vsync on, and
  checks power-mode and blank.

## D2a: probe stops at the TE interrupt

- **Image:** BOOT `src/m72/boot-d2a.img`, sha256 `07448febda6be01ae9f5e9e10b36dcc8f1b5ffe296b8f1c258fbce5d1c5b8f67`
  ([inputs](../reference/m72-display/d2a-inputs.json)).
- **USB SSH worked this time.** The early log ([live](../reference/m72-display/d2a-live-deferred.txt)) shows the probe
  reached `handover state GLOBAL=0x00000133 TRIG=0x00003010 FRAME_COUNT=3, 5 clocks enabled` and then failed with
  `error -6: te irq`. No fb device existed, so `fb_test` didn't run.
- **Cause:** the 6.18 table for the Exynos 9610 TOP pin controller has no `.eint_gpio_init`, so `gpc2` has no interrupt
  domain. Samsung's 4.14 table has `.eint_gpio_init = exynos_eint_gpio_init` for that controller
  (`pinctrl-exynos-arm64.c:540`), and the stock DECON node lists the controller's combined interrupt, SPI 266.
- **Restore:** stock restored by the runner; post-flight passed; fsck clean, 6524 files
  ([run](../reference/m72-display/d2a-run.txt), [fsck](../reference/m72-display/d2a-baseline-fsck.txt)).
