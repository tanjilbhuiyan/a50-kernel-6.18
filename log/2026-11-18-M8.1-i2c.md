## Offline analysis (unverified until measured)
- 6.18 `s3c24xx_i2c_probe` (drivers/i2c/busses/i2c-s3c2410.c): select pinctrl, `clk_prepare_enable(clk "i2c")`,
  `s3c24xx_i2c_init` (writes IICCON/IICSTAT), `clk_disable`, then `devm_request_irq`. The IRQ handler reads IICSTAT and
  writes IICCON without enabling the clock, so any interrupt outside a transfer accesses the block with its clock gated;
  on Exynos such an access can stall the interconnect silently.
- Interrupt numbers in M4.4 match stock (SPI 247/248/250/251/253, `reference/stock-dt/dt.dtb.0.dts` ~3911-4023); stock
  trigger type is 0, M4.4 used level-high.
- Clocks differ: M4.4 used `CLK_GOUT_PERI_I2C_n_PCLK` (CLK_CON_GAT 0x204c+). Stock uses `GATE_I2C_n_QCH`
  (4.14 `include/dt-bindings/clock/exynos9610.h`: 0x22b..0x231) for both `rate_i2c` and `gate_i2c`; these are the
  Q-channel controls `QCH_CON_I2C_n_QCH` at CMU_PERI 0x301c+ (4.14 `pmucal_system_exynos9610.h`). Samsung CAL
  (`cal-if/ra.c ra_req_enable_qch`) does nothing when the Q-channel ENABLE bit is set and only drives CLOCK_REQ when it is
  clear: stock relies on the hardware Q-channel.
- The 6.18 Samsung clock init forces every CMU gate in the registered range into manual mode (patch 0006) when automatic
  gating is not used; CMU_PERI also holds the GPIO and MCT bus clocks (0x2048, 0x206c).
- The functional I2C clock (`DIV_CLK_PERI_I2C` 0x1800, `GATE_CLK_PERI_I2C` 0x2008, `GOUT_PERI_I2C_CLK` 0x207c) is not
  referenced by the M4.4 DT.

## T3 result (owner: "present, flash T3"; office 192.168.181.225): freeze reproduced and caught
BOOT `src/m81/boot-t1.img`, DT `src/m81/dt-t3.img`. Flash 12:14:55; no USB networking (watch rc 1); 6.18 returned to
Download mode by itself 12:16:06 (panic dump); stock restored 12:16:23; baseline up 12:16:37; post-flight passed; fsck
clean 7050/3440640 files. Dump `reference/m81-i2c/t3-dump.txt` (`dump_after` header: `panic`).
- `/clock-controller@10030000: incorrect res size for automatic clocks` (x2): the 0x8000 window selects the manual
  gate path, as intended.
- I2C probed at 0.050 s: `s3c-i2c 13870000.i2c: bus frequency set to 378 KHz`, adapter `i2c-0` registered.
- 0.108 s: new warning, `a50-decon 148b0000.decon_f: late IOMMU probe at driver bind, something fishy here!`
  (WARN in `__iommu_probe_device`, from `a50_decon_driver_init`), on **CPU 4, PID 1** (the initcall thread). Not seen
  in the T1 or I4 dumps (whose early lines are wrapped out of the 128 KB buffer, so its absence there is not proof).
- 0.338 s: `Unpacking initramfs...` / `Initramfs unpacking failed: invalid magic ...` (async), then **no further boot
  messages**.
- 21.1 s: RCU stall on CPU 4 (`4-...0`, t=5252 jiffies, i.e. since about 0.1 s); 31.1 s: `watchdog: CPU3: Watchdog
  detected hard LOCKUP on cpu 4`; NMI requests to CPU 4 produced no backtrace; 41.1 s: `Kernel panic - not syncing:
  Hard LOCKUP`; `SMP: failed to stop secondary CPUs 4`.

Interpretation: CPU 4, running the boot initcalls, stopped inside an access that never completed (it ignored IPIs/NMIs
and the stop request), the signature of touching a block whose clock is off. **Acceptance 1 is met by bisection:** T1
and T3 differ in one DT variable, the I2C clock provider (6.18 CMU_PERI clock driver in manual mode + real I2C_4 PCLK
vs bootloader state + fixed clock), and only T3 freezes.

Mechanism (unverified): the bootloader runs CMU_PERI in global automatic gating (option register `0x30000000`); with a
0x8000 window `exynos_arm64_init_clocks()` sets `GATE_MANUAL` on every PERI gate (`clk-exynos-arm64.c`), so any gate
whose value bit is 0 becomes hard off, and the I2C driver's `clk_disable` after init hard-gates `I2C_4_PCLK`. CMU_PERI
also clocks the TMU bus interface (`BUSIF_TMU` PCLK 0x2024, 4.14 `cmucal-sfr.c:1086`), and 6.18 runs a read-only TMU
driver (`thermal-sensor@10070000`) since M4.6. R1 read only some gates (all value 1); 0x2024 and the rest were not read.
The driver's automatic mode (`samsung_is_auto_capable()` requires a 0x10000 window) writes the global auto-gating option
and keeps gates under hardware control, matching the bootloader/stock (HWACG/Q-channel) model.
