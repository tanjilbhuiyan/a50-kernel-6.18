## Observation method

`tools/m53/make_status_init.py` reads the original Halium /init from the
M3.7 embedded list and inserts a chrooted background observer just before
switch_root. It embeds `tools/m53/systemd_status.sh` inline, so no observer
file is needed after the initramfs is removed. The observer enters the
mounted Ubuntu root while /proc, /sys, /dev and /run are available, then
signals readiness using a marker in tmpfs /run. The parent waits up to five
seconds for this handshake, preventing deletion of initramfs executables
before the child enters its new root. Halium's original handoff is retained.

Snapshots at uptime 60, 120 and 200 seconds capture uname, actual
`systemctl is-system-running`, failed units, pending jobs, multi-user/graphical
target states, manager state and userdata mount. Each command has a four-second
timeout; return codes are recorded, including systemctl's nonzero status for
degraded/starting states. Output goes directly to /dev/kmsg with A50STATUS
prefixes. Temporary files and handshake are only in /run (tmpfs); no rootfs
services, persistent configuration or USB functions changed.

Generated files: `src/m53/halium-init-status`,
`src/m53/embed-status.list.in`; source diff:
`reference/m53-halium-init/test4-init-observer.patch`.
Host checks: `sh -n` on observer and generated init passed; embedded list
diff has exactly one changed entry (/init); kernel diff exactly matches
the test-3 guard patch; resolved .config is byte-identical to test 3.
