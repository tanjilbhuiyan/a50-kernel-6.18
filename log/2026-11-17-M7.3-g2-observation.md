This follow-up checks the existing G2 evidence and records the owner's
screen report. No additional phone operation, build or flash was performed.

## Recorded test

Inputs: `reference/m73-gpu/g2-inputs.json`. Source
`a50-m73-g1-wip/c04d5ada5`, tree `2c8ab17e16c68ae7a72ed3c814f08d39894e5413`
(same source as G1b). The single config change removes
`mali_kbase.a50_g1_probe_only=1`; DTB and embedded runtime remain unchanged.
BOOT SHA-256 `bf0934e7f727502e615be471d1fec9c93ab0c83b2b369c72dc3c59a87276e93a`.

`g2-live.txt` records the first `test_egl` failure loading libhybris's
linker because of insufficient static TLS. A login shell supplies
`GLIBC_TUNABLES=glibc.rtld.optional_static_tls=4096`. The later
`test_glesv2` attempt begins at 01:21:22; no successful rendering result
or pixel readback is recorded.

`g2-dump.txt` contains 300 `Atom ... still waiting for fence ... after
3000ms` messages for client context `4021_7`. All 300 accompanying guilty
fence records have fence context 1 and remain active. This establishes
queued work and a synchronization stall; it does not establish successful
GPU completion. The owner of dma-fence context 1 is **unverified**. The
display release-fence/CPU-copy explanation remains a hypothesis.

At uptime 123.028 s the kernel reports a NULL dereference at address
0x68, PC `kbase_cancel_soft_job+0x1c/0x11c`, followed by panic. The tested
source's `MALI_SEC_INTEGRATION` block obtains `katom->kctx->process_mm`
and calls `pgd_offset(mm, (unsigned long)katom)` before cancellation.
It walks a process page table for a kernel pointer and is unsafe during
process teardown. The handoff attributes cancellation to the timeout
killing the hung client. Proposed next fix: remove this vendor check,
retaining the actual fence/event cancellation paths.

## Owner observation

The owner reports that during the GLES test the screen went black from
the top, flickered a couple of times, then became fully black. It later
rebooted to the Ubuntu UI. No recognizable triangle or animation was
reported. Treat this as **blackening/flicker**, not confirmed rendered
content. It does not distinguish GPU/fence failure from a presentation
problem or establish a throughput-only limitation.
