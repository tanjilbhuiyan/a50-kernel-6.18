## Port (branch a50-usb on a50-ufs; patches reference/m36-usb/). Built, not yet tested on the phone.
Facts: stock DT usb@13200000 (DWC3, IRQ SPI 0xba = 186), USB 2.0 PHY phy@131D0000 (phy_version 0x300), USB3 PHY phy@131F0000 (not used), PMU isolation 0x704 mask 3, is_not_vbus_pad = 1.
No 9610 USB support in mainline (checked torvalds/linux history of phy-exynos5-usbdrd.c and dwc3-exynos.c).
- PHY: "samsung,exynos9610-usbdrd-phy" in phy-exynos5-usbdrd.c. Register layout equals Exynos850 (4.14 phy-exynos-usb3p1-reg.h vs EXYNOS850_DRD_*). Dedicated utmi init instead of exynos850_usbdrd_utmi_init, because
  mainline branches on LINKPORT_HOST_NUM_U3 (ss_ports) and may pick the PHY20 reset bits, while Samsung's v3.0.0 minor 0 path uses PHY_SW_RST + PHY_RST_SEL + PORT_RST. Sequence = phy_exynos_usb_v3p1_enable(): Q-channel workaround, link reset,
  POR high, UTMI+, HSP (common_block_disable=1), filter bypass, FORCE_BVALID/VBUSVALID + VBUSVLDEXT(SEL) (unconditional, the sm5713 bypass), HSP tune, SIDDQ clear, POR low, OCD select.
  Tuning: stock dtbo.5 usb_hs_tune, device column (USBPHY_MODE_DEV = 0): vref 0xf, pre_emp 3, pre_emp_plus 0, res 3, rise 3, hsxv 3, fsls 3, sqrx 7, compdis 7, otg 2. Isolation mask 3 (mainline's generic isol only touches bit 0).
- Controller: "samsung,exynos9610-dwusb3", fallback exynos850-dwusb3 (clocks bus_early, ref = GOUT_USB_USB30DRD_BUS_CLK_EARLY / REF_CLK); child snps,dwc3 dr_mode=peripheral, maximum-speed=high-speed, snps,dis-u2-freeclk-exists-quirk (stock).
  Peripheral only: VBUS never driven; the sm5713 USB-C chip is left as the bootloader set it.
- vdd10/vdd33: binding-required; placeholder reg_dummy as on exynos850-e850-96 (the stock DT gives the USB nodes no supply). True rails: M4. If the rails are off in normal boot, the gadget will not enumerate.
- DT: dtc W=1 clean; dt-validate clean; negative test (bogus clock-name) flagged. My first PHY-binding edit produced invalid YAML ("error parsing file") and was committed in a chained command; fixed and amended before use.

## Investigation (2026-11-08): the sm5713 MUIC leaves the USB data lines open
4.14 drivers/muic/sm5713-muic.c routes D+/D- by I2C: com_to_usb() = set_manual_sw(true) (CFG1 bit 2) + MANUAL_SW (reg 0x06) = MANSW_USB (0x09); com_to_open() writes 0. The baseline kernel does this after detecting a USB attach.
S-Boot's own log of the chip (/proc/last_kmsg): "[MUIC] print_init_regs ... CTL:34 ... T1:02 ... MS:00" then "init CONTROL:0x24", "init CFG1:1a -> 1a": MANUAL_SW = 0 = open. Nothing on 6.18 changes it. Matches Tests 1-2 (controller ready, no attach ever seen). Strong but UNVERIFIED until the switch is set and the gadget enumerates.
Reaching the chip: bus i2c-1 = controller at 0x13840000, compatible "samsung,s3c2440-i2c" (mainline i2c-s3c2410 supports it), IRQ SPI 0xf8. busybox in the initramfs has i2cget/i2cset/i2cdump/i2cdetect.
