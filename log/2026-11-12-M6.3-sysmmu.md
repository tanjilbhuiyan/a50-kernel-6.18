# 2026-11-12 M6.3 SysMMU provider preparation

Source `a50-m63-sysmmu-test/bd3fe49b2d2c3b0b04be490b3440d38d806949a3`
adds an isolated DPU provider DT on top of the tested ION source. The kernel
build enables `IOMMU_SUPPORT`, `EXYNOS_IOMMU` and the native driver's debug
option. The first boot uses the previous DT to check the config change.
The second uses the same BOOT image with the new provider DT. No DMA master
has an `iommus` link to it.

## Mapping and source checks

The ten stock nodes cover VIPX1/2, MFC0/1, G2D/MSCL/JPEG, CAM,
ISP/VRA/GDC, MCSC, DPU and ABOX. Their reserved/secure IRQ and vendor power
properties require separate treatment from the native nonsecure binding.
The provider test selects DPU, in DISPAUD, which the earlier M4.5 readout
and baseline display state establish as powered at boot.

- DPU register window is `0x14820000` for `0x9000` bytes. The stock first
  interrupt is SPI 218; its separate secure bank and secure interrupt are
  omitted from this nonsecure provider test. Source is
  `reference/stock-dt/dt.dtb.0.dts` at `sysmmu@14820000`.
- The stock node has only `aclk`. ACK's `exynos_sysmmu_probe` accepts
  `sysmmu` or both `aclk` and `pclk`. The target uses the existing native
  `CLK_GOUT_DISPAUD_SMMU_DPU_CLK` with the `sysmmu` name.
- CMU_DISPAUD is at `0x14980000`, from the donor's
  `drivers/soc/samsung/cal-if/exynos9610/cmucal-sfr.c`. The DT uses a
  `0x8000` window to retain the manual CMU mode used in M3.3. Its three
  CMU_TOP parent clock IDs follow the target's existing binding.
- The native driver supports v7 capability registers and selects its
  variant from the hardware version register. Its probe reads the version,
  registers the provider and enables runtime PM. Page-table attachment and
  translation writes belong to the later master attachment path.
- The test omits power-domain switching. Stock domains require secure
  firmware control, which remains deferred. Real display DMA, fault
  handling, suspend/resume and secure SysMMU access remain untested here.

## Build and validation

Config derives from `out/m63-ion-compat/.config`. Use the pinned build
environment from the ION/ashmem logs and `out/m63-sysmmu` as the fresh
output directory. Build `Image` and `exynos/exynos9610-a50-sysmmu.dtb`, pack
BOOT with `tools/m22_pack.sh`, and pack DT with
`tools/dt_table.py build reference/stock-images/dt.img src/m63/dt-sysmmu.img --set 0=DTB`.
The stock DTBO restore and no-op overlay test image follow the existing runner.
[Source patch](../reference/m63-sysmmu/0001-dpu-sysmmu-probe.patch) ·
[Config delta](../reference/m63-sysmmu/config-delta.txt) ·
[Input hashes](../reference/m63-sysmmu/inputs.json).

The SysMMU and Exynos9610 CMU nodes passed their binding schemas with
dtschema 2026.9. A negative control changed `clock-names` to the invalid
single `aclk`; the validator rejected it. Validation was limited to the
two changed node schemas. [Negative control](../reference/m63-sysmmu/dt-negative-control.txt).

BOOT `src/m63/boot-sysmmu.img` SHA256
`de28abe867bf95c65e89fc3fd5a7369ed64f899f31cf1d5a466af9fa12c92d90`.
The control uses `src/m48/dt.img`. The provider test uses
`src/m63/dt-sysmmu.img`, with the same kernel/config/cmdline.

Both tests run the native and compat ION replay, verify exported buffers
return to zero, and restore/check the baseline. The provider test also
requires the `14820000.iommu` device bound to `exynos-sysmmu` and captures
the driver's hardware version and any deferred probe output.

## Provider live result

The same BOOT flashed with the provider DT at 19:37:22. Root SSH was
verified through USB at 19:38:09. `14820000.iommu` bound to `exynos-sysmmu`;
the native driver read **hardware version 7.2** at 0.041185 seconds. The
deferred-device listing was empty. Both replay helpers passed all captured
allocations and boundary/lifetime tests, with zero exported objects and
bytes afterward. [Provider probes](../reference/m63-sysmmu/probe-smoke.txt) ·
[USB route verification](../reference/m63-sysmmu/probe-watch.txt).

This establishes the DPU clock/provider probe path. No master is attached:
IOVA allocation, page-table walks, DMA/cache coherency, fault interrupts,
secure mappings and suspend/resume remain unverified. The other nine stock
controllers are mapped in the design but are not enabled by this DT.

The timed dump returned to Download at 19:42:00 and stock restored at
19:42:17. Baseline boot time was 19:42:30, battery 100% Charging. Post-flight
verified stock DTB/DTBO and baseline BOOT hashes; baseline init's saved fsck
reported clean, 6320/3440640 files and 1986780/13745152 blocks, no repairs.
[Runner and post-flight](../reference/m63-sysmmu/probe-run.txt) ·
[Saved baseline fsck](../reference/m63-sysmmu/probe-baseline-fsck.txt).

Both SysMMU dumps have a passing guard self-test, the unchanged userdata
allow-list, exactly one denied UNMAP, and all three userdata snapshots rw.
By 120 seconds systemd was degraded with zero jobs and the same four

WRITE(6) fallbacks, panics or DMA-BUF accounting warnings. No temporary host
NetworkManager profile was created in either test.

## M6.3 acceptance

All four builds/boots passed their intended checks and stock restore.
Across them, seven helper runs replayed 224 captured allocations; each
completed its boundary/lifetime checks and exported buffers returned to
zero. The [result summary](../reference/m63-ion/results.json) is derived
from the saved probes, dumps, post-flights and fsck outputs.

M6.3 is complete for the measured heap-0 ABI and isolated provider
preparation. This does not establish the remaining six reserved/secure
heaps or full vendor allocator compatibility. M6.4 must run the actual
allocator service and revisit any newly observed heap requirements.
Actual DMA remains for M7 or the relevant consumer milestone. Android
stayed STOPPED with the existing diagnostic service masks; no M6.4 startup
test was performed. Stock vendor/protected partitions were unchanged.

Kernel source is committed on the two test branches listed above, with
patches exported under `reference/`. The checkout is back on clean
`a50-usb/4fbb731f5`. Outer base remains `a829080`; M6.2 wakelock and M6.3
tools, evidence and handoff changes remain uncommitted.

Final host checks verified both M6.3 input manifests against the files,
exact replay/capture agreement, local documentation links, shell/Python
syntax and `git diff --check`. Hardware identifiers in evidence copies
are redacted; runner byte counts describe the copies before the additional
MAC/link-local redaction and trailing-whitespace cleanup.
