# 2026-11-11 M6.2 BinderFS control and candidate

First interface test from the [M6.1 audit](2026-11-11-M6.1-android-runtime-abi-audit.md#first-m62-test--isolated-binderfs).
Outer base `0ebaf48` with the uncommitted M6.1 audit. The kernel started on
clean `a50-usb/4fbb731f5`. Both final images use test branch
`a50-m62-binder-test/e8a5a7feaa7dbb5c5fc8d8e87db6c209a770bee6` on top of
M5.4 `f0618ab59`, with its USB rescue init and 240-second diagnostic dump.

## Build

The [control delta](../reference/m62-binderfs/control-from-m54.txt) changes
only the built-in command line, adding
`systemd.mask=mount-android-partitions.service`. This stops the Android mount
script and dependent container startup for both boots. The
[candidate delta](../reference/m62-binderfs/candidate-from-control.txt) enables
C Binder and BinderFS, sets the three Binder device names, and enables
FTRACE and default tracers for the required `EVENT_TRACING`. The full delta
also records the tracing menus and defaults, including uprobes and BPF event
support. The command line, UFS guard range, and USB configuration match the
control. The embedded cpio is byte-identical across M5.4 and both M6.2 builds.

The first Binder build failed because ACK builds `power-traces.o` with
`TRACEPOINTS`, and its device PM callback exports referenced definitions that
only exist under `CONFIG_PM_SLEEP`. Both final images were built from the
test commit that applies the same guard to the exports. PM and suspend remain
disabled in both configs. [Compiler evidence](../reference/m62-binderfs/power-trace-build-error.txt) ·
[Kernel patch](../reference/m62-binderfs/0001-guard-device-pm-tracepoint-exports.patch).

Both final builds passed with `KBUILD_BUILD_VERSION=1`, so their build number
and timestamp match after the incremental rebuilds. The candidate adds
2,308,096 bytes to the packed image. The BOOT budget is 57,671,680 bytes.
[Input hashes](../reference/m62-binderfs/inputs.json).

Build from the outer repository with the kernel on the pinned test commit.
Use fresh output directories. `tools/m22_build.sh` replaces its output
directory and uses the ACK r584948c Clang toolchain.

```sh
out=src/ack-6.18/out
artifact=src/m62
mkdir -p "$artifact"
export A50_HALIUM=1 A50_DIAG=1 A50_DIAG_DUMP_DSS=1 A50_DIAG_DUMP_AFTER=240
export KBUILD_BUILD_VERSION=1

export A50_CMDLINE_APPEND='clk_ignore_unused printk.devkmsg=on systemd.log_target=kmsg systemd.journald.forward_to_kmsg=1 systemd.show_status=1 systemd.mask=rild.service systemd.mask=ofono.service systemd.mask=bluebinder.service systemd.mask=a50-audio-route.service systemd.mask=mount-android-partitions.service'
base_flags=$(sed -n 's/.*A50_CONFIG="\([^"]*\)".*/\1/p' log/2026-11-10-M3.7-halium-initramfs.md)

binder_flags='-e FTRACE -e ENABLE_DEFAULT_TRACERS -e ANDROID_BINDER_IPC -e ANDROID_BINDERFS --set-str ANDROID_BINDER_DEVICES binder,hwbinder,vndbinder'
A50_CONFIG="$control_flags" tools/m22_build.sh "$out/m62-binder-control"

tools/m22_pack.sh "$out/m62-binder-control/arch/arm64/boot/Image" "$artifact/boot-binder-control.img"
tools/m22_pack.sh "$out/m62-binder/arch/arm64/boot/Image" "$artifact/boot-binder.img"
```

The guard boundary test passed with 14/14 mutants caught. The sense test
passed and caught both the old WRITE(10) fallback and the repeated-discard
regression. Both used the real source on `f0618ab59`. The final test commit
has the same UFS and SCSI source as that base.
[Boundary output](../reference/m62-binderfs/guard-host.txt),
[sense output](../reference/m62-binderfs/sense-host.txt).

Compile the AArch64 smoke helper using NDK r27's static libc and the Binder
UAPI from the pinned kernel. The built ELF is AArch64 with no interpreter.
The helper checks device numbers and runs `BINDER_VERSION` on all three
contexts. Kbuild `rustavailable` also passed with ACK Rust `1.91.1.p3`,
Clang r584948c and bindgen 0.72.1 for the later ashmem test.

    -I src/m62/include tools/m62/binder_smoke.c -o src/m62/binder-smoke

## Live procedure

Verify baseline pre-flight with the owner present. Run the control first.
For each boot use the [M5.4 USB watcher](../tools/m54/watch_ssh.py) and verify
that the USB route leads to authenticated root SSH on the running 6.18
kernel. The [device-side check](../tools/m62/check_binderfs.sh) verifies the
mask, Android `STOPPED` and userdata rw before attempting the mount. The
control requires an absent filesystem. The candidate requires a working mount
and all three context devices. Any helper staging is under `/run`.

```sh
usb_ssh=(-o BatchMode=yes -o StrictHostKeyChecking=yes -o HostKeyAlias=192.168.0.171 root@10.15.19.82)
# On the control, after the USB watcher verifies the route and kernel:
ssh "${usb_ssh[@]}" 'sh -s -- control' < tools/m62/check_binderfs.sh
# On the candidate, after repeating that verification, stage in /run:
ssh "${usb_ssh[@]}" 'umask 077; mkdir /run/a50-m62 && cat > /run/a50-m62/binder-smoke && chmod 700 /run/a50-m62/binder-smoke' < src/m62/binder-smoke
ssh "${usb_ssh[@]}" 'cat > /run/a50-m62/check_binderfs.sh' < tools/m62/check_binderfs.sh
# /run is noexec. Use a private executable tmpfs for the binary:
ssh "${usb_ssh[@]}" 'sh -s' <<'REMOTE'
set -eu
dir=$(mktemp -d /run/a50-m62-exec.XXXXXX)
mounted=0
cleanup() {
    if [ "$mounted" = 1 ]; then umount "$dir"; fi
    rmdir "$dir"
}
trap cleanup EXIT
mount -t tmpfs -o size=4m,mode=0700,nosuid,nodev,exec tmpfs "$dir"
mounted=1
cp /run/a50-m62/binder-smoke "$dir/binder-smoke"
chmod 700 "$dir/binder-smoke"
sh /run/a50-m62/check_binderfs.sh candidate "$dir/binder-smoke"
REMOTE
```

Archive each SSH check, systemd state and unit failures, timed dump, baseline
pre-flight and the saved `/run/e2fsck.out` after rollback. Compare the dumps
for protected write denials, userdata errors and USB behavior before moving
to ashmem.

The owner confirmed presence, Claude Code idle, and authorized the M5.4
runner's Heimdall DTB/DTBO/BOOT flash and restore for both BinderFS tests.
Pre-flight at 05:40 verified 4.14.194, full battery, stock DTB/DTBO and
baseline BOOT at `192.168.0.171`. [Pre-flight output](../reference/m62-binderfs/preflight-before.txt).

## Control result

Control flashed at 05:42:13. At 05:43:00 root SSH reached 6.18 over USB
`enp6s0f3u1` at `10.15.19.82:22`. The Android partition unit was masked,
Android was `STOPPED`, and userdata was rw. `mount -t binder` returned 32
with `unknown filesystem type 'binder'` and Binder was absent from
`/proc/filesystems`. That reproduces the failure mode suspected in the M6.1
audit when the filesystem is missing. The original M5.4 unit's exact failing
command remains unverified. [USB route and SSH](../reference/m62-binderfs/control-ssh.txt) ·
[Control probe](../reference/m62-binderfs/control-binder.txt).

The dump shows the guard self-test passed, the LUN 0 userdata range was
active, and the only denied SCSI command was one UNMAP. The EFS write denial
from M5.4 did not recur. Userdata stayed rw. The observer saw degraded with
zero pending jobs at 121 and 200 seconds. The fake coldplug unit failed with
Android startup masked. Its archived service file requires either the LXC
config unit or real coldplug unit to be active. [Control dump](../reference/m62-binderfs/control-dump.txt).

The phone returned to Download at 05:46:52. Stock DTB/DTBO and baseline BOOT
uploaded at 05:47:09 and all three live hashes matched in post-flight.
Baseline init's `e2fsck` reported clean, 6314/3440640 files. [Runner](../reference/m62-binderfs/control-run.txt) ·
[Saved fsck](../reference/m62-binderfs/control-baseline-fsck.txt).

## Candidate result

The candidate flashed at 05:48:44 and root SSH reached 6.18 over USB
`enp6s0f3u1` at 05:49:31. BinderFS mounted with `stats=global` and exposed
four distinct character devices. The first smoke invocation failed because the existing
`/run` mount is `noexec`. Within the same boot the helper ran from a private
executable tmpfs mounted under `/run`. It opened all three IPC nodes and
reported `BINDER_VERSION=8` for each. The probe unmounted BinderFS and the
temporary tmpfs. The Android partition service remained masked, Android was
`STOPPED`, and userdata was rw. [First attempt](../reference/m62-binderfs/candidate-binder.txt) ·
[Successful retry](../reference/m62-binderfs/candidate-binder-retry.txt) ·
[USB route and SSH](../reference/m62-binderfs/candidate-ssh.txt).

Both dumps show the same seven failed units and zero pending jobs at the
121- and 200-second snapshots. The userdata guard reported the same range,
one UNMAP refusal and no other SCSI command denial. Userdata was rw at all
three snapshots with no journal abort or read-only remount. [Candidate dump](../reference/m62-binderfs/candidate-dump.txt).

The candidate returned to Download at 05:53:23. Stock DTB/DTBO and baseline
BOOT uploaded at 05:53:40, and post-flight verified all three live hashes.
Baseline init's fsck reported clean, 6317/3440640 files and
1974692/13745152 blocks. The runner exited 0. Its surrounding shell retained
126 from the first helper invocation, and the separate same-boot retry
exited 0. [Runner](../reference/m62-binderfs/candidate-run.txt) ·
[Saved fsck](../reference/m62-binderfs/candidate-baseline-fsck.txt).

BinderFS interface test passed. Next, enable native ACK Rust ashmem in a
separate candidate using the Binder build as the comparison. Keep the Android
partition mask and USB test path for the remaining isolated interface tests.
