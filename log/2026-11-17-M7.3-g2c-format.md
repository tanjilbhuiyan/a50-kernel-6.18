# 2026-11-17 M7.3 G2c: stock WIN_CONFIG format translation

Session by Claude Code. The owner said "present, flash G2c" before the flash; Codex was idle. Home network, phone
`192.168.0.171`; backup hash matched. G2b's tested source was committed first (`530351ed2`, tree `89009e6d9e91`).

## Change and build

- **The single variable compared with G2b:** kernel commit `e3d95f7b8` on `a50-m73-g2c-wip` (worktree
  `src/m73/g2b-kernel`; patch `reference/m73-gpu/g2c-format.patch`). `a50-decon` now translates the submitted ABI format
  (Android byte order) to the DPP/IDMA format (32-bit word order), as the stock driver does in
  `dpu_translate_fmt_to_dpp()` (4.14 `helper.c`), called from `decon_core.c:2574`:
  - ARGB↔BGRA, ABGR↔RGBA, XRGB↔BGRX, XBGR↔RGBX;
  - the CPU-copy fallback converts all eight 8888 word orders;
  - logging only: the sampled `WIN_CONFIG` log adds the DPP code and the source/destination geometry.
- **Host test:** `tools/m73/format_unittest.py` encodes one colour in each ABI byte order. All 8 convert to the same ARGB
  word. Three deliberately broken variants fail (the M7.2 pass-through fails all 8, which shows the M7.2/D2b test tool's
  use of ABI value 1 for R,G,B,A bytes was not the stock meaning). The guard, sense, mmap and cancel tests also pass.
- **Build:** `tools/m73/build_g2c.sh`. Config, DTB and runtime cpio are byte-identical to G2/G2b. BOOT
  `src/m73/boot-g2c.img`, sha256 `d6df1ecc7ed57904e6b24c4f83be1d8f33348260094e20f4152b7fffbad60bbc`
  ([inputs](../reference/m73-gpu/g2c-inputs.json)).
- **Test tool:** `tools/m72/winconfig_test.c` now submits R,G,B,A bytes as ABI `RGBA_8888` (2) and adds test 5, the same
  four colour bands encoded in turn as ARGB, RGBA, BGRA and ABGR.

## Result

- **Translation works for the composer's frames.** The sampled log shows the composer layers as
  `format=2 dpp=1 src=1080x2340+0+0/1080x2340 dst=1080x2340+0+0 dma_eligible=1`: full screen, stride 1080, and now
  DMA-eligible. Driver counters: 42 `WIN_CONFIG`s, **36 scanned by DMA**, 0 copied, 0 skipped.
- **But the panel was asleep for every one of them:**
  - From 32.7 s to 39.4 s the driver logged five blank/unblank pairs, ending with a blank. TE then stopped at a count of
    1995 and never resumed (live checks at 88 s and 106 s; late log `te=1995`).
  - With no TE, every frame request timed out: late log `frames req=41 done=6 timeouts=36 frame_wait_timeouts=36`.
  - Hence `winconfig_test` (run at about 45 s, after the final blank) measured late fences:
    `test1 103 ms`, `test3 not signalled in 504 ms`, `test4 504 ms per frame`, `test5 not signalled`, `RESULT: FAIL`.
  - Those numbers come from the blanked panel, not from the format change.
- **Who blanked it:** LightDM. `lightdm.service` ended `failed`. `/var/log/lightdm/unity-system-compositor.log` shows Mir
  getting much further than before:
  1. it loads `graphics-android2`;
  2. it opens HWC2 through `libhwc2_compat_layer` (`Error opening HWC HAL. Assuming HWComposer 2 device`);
  3. `hotplug: Adding display 0`, `Found 1 matching egl configs`;
  4. then `gralloc_module.cpp(75): ... alloc_buffer ... buffer allocation failed`, errno 12 (`Cannot allocate memory`).

  Each restart powers the display on and off; the timing matches the toggles. `libminisf.so` is absent (fake
  SurfaceFlinger not started), which Mir reports as informational.
- **Unexplained:** the failing gralloc request. The M6.3 ION compatibility layer supports only heap 0 and rejects other
  masks or flags without logging, and the kernel log has no ION messages. Mir's framebuffer-target allocation may use
  another heap or usage bits. Unverified.
- **No faults:** no `Unable to handle`/`SError`/`BUG`/panic lines in the dump ([dump](../reference/m73-gpu/g2c-dump.txt)).
- **Restore:** post-flight passed (4.14 back, stock DTB/DTBO/BOOT); baseline fsck clean, 6521/3440640 files
  ([run](../reference/m73-gpu/g2c-run.txt), [fsck](../reference/m73-gpu/g2c-baseline-fsck.txt)). Live captures:
  [g2c-live.txt](../reference/m73-gpu/g2c-live.txt), [g2c-lightdm.txt](../reference/m73-gpu/g2c-lightdm.txt).

## Next (G2d proposal)

- **Kernel, logging only:** the ION compatibility layer logs every request it rejects or fails (heap mask, flags,
  length, error), rate-limited. That identifies Mir's failing gralloc allocation.
- **Test tool:** set `S3CFB_POWER_MODE` NORMAL before testing, so a blank left by LightDM can't hide the known-colour
  test.
- M7.3 rendering acceptance remains open. The separate `test_egl` SIGSEGV (G2b) is still uninvestigated.
