## 2. Minimal port design

Every stage keeps the M6 baseline: the UFS guard and userdata range, USB SSH, the headless Android startup with the allocator,
the ADR-0004 TEEGRIS deferral, the approved power masks, and the same DT/DTBO/BOOT runner with stock restore.

1. **Keep the bootloader's display and power state.** Domains stay on (no domain control), no runtime PM, clocks stay on
   via `clk_ignore_unused`, and the panel isn't power-cycled until the GPIO sequence has been checked. No ACPM DVFS.
2. **Display through fbdev, not DRM.** The stock composer needs `/dev/graphics/fb0` with `S3CFB_*` ioctls, and fbdev still
   exists in 6.18. Port the 9610 subset of DECON, DPP, DSIM and CAL and the EA8076 panel. Replace Samsung IOVMM/ION mapping
   with dma-buf attach/map on the DPP device behind the native DPU SysMMU. Drop BTS, DisplayPort, ABD, MDNIE, DPUI,
   content protection and `sec_debug`.
3. **IOMMU last, with an identity region.** Before any display device is attached to SysMMU, give the boot framebuffer
   (`0xca000000`) an `iommu-addresses` identity mapping (Samsung's `iovmm_map_oto` does the same). Until then, scan out only
   physically contiguous memory (the boot framebuffer).
4. **Mali kbase r26p0 with a fixed-clock platform layer:** no DVFS, no runtime PM, no protected mode, no SMC, G3D domain
   left on. Keep the full ioctl set and the 32-bit compat paths.
5. **G2D only on evidence (M7.4).** Start without `/dev/g2d`. Port the driver only if the composer fails without it, or a
   Lomiri scene needs more than 4 layers.

## 3. First boot variables (one per boot) and rollback

Rollback for every boot: `tools/m32_run_test.sh` (directly or through a wrapper) restores stock DTB/DTBO and the baseline
BOOT, then checks the phone, saves baseline init's `/run/e2fsck.out`, and confirms the runtime overrides are gone.

| Boot | Single variable | Pass evidence |
|---|---|---|
| D0 | Read-only display state probe: dump the DECON, DSIM and DPP registers left by S-Boot (enable, command/trigger mode, window 0 base = `0xca000000`, TE). No writes | Register values match the stock DT and the boot framebuffer |
| D1 | Minimal handover: draw a pattern into the boot framebuffer and request one DECON frame update, with everything else as left by S-Boot. No IOMMU, no PHY, no panel power | Pattern visible on the panel (owner observes) |
| D2 | DPU20 fbdev core with the EA8076 panel in "already on" mode, `fb0` exposed with `S3CFB_*`; no SysMMU attach yet | `S3CFB_WIN_CONFIG` from a host test with a physically contiguous buffer appears on screen; vsync events arrive |
| D3 | Attach DPP to the DPU SysMMU with the boot-framebuffer identity region; scan out ION heap-0 dma-bufs | Composer frames appear; no SysMMU faults in the dump |
| D4 | Blank/unblank through the panel GPIO sequence | FBIOBLANK and `S3CFB_POWER_MODE` cycle the panel and it comes back |
| G0 | Read-only GPU ID probe (Mali registers at `0x11500000`) with G3D on | GPU_ID matches Mali-G72 |
| G1 | kbase r26p0 with the fixed-clock platform layer, `/dev/mali0` | VERSION_CHECK and GET_GPUPROPS from a host test, both 64- and 32-bit |
| G2 | libhybris GLES test on the host, then Lomiri | Off-screen render, then accelerated Lomiri, then the M7.5 soak |

The display track (D0–D4) and the GPU track (G0–G2) are independent until M7.5.

## 4. Hardware prerequisites

- **Display needs neither M4.4 (I2C) nor M4.3 (S2MPB03):** the panel uses GPIOs, and S2MPB03 feeds only cameras (section 1).
  The M7.2 dependency on them is therefore removed. Touch is on I2C and stays an M8 matter.
- Still needed: DT nodes for the DISPAUD, G2D and G3D CMUs when drivers take clock handles; a 9610 MIPI D-PHY description
  only if the DSI link is ever reinitialised (from D4 on).
- Unverified risks: MIF bandwidth without BTS (D2/D3), and GPU throughput at the fixed bootloader clock (G2, M7.5 soak).

## 5. Legacy cgroup profiles and TEEGRIS for M7 consumers

- **cgroups.** Init fails `createProcessGroup` on the read-only v1 path for every service, including `vendor.hwcomposer-2-1`,
  and `libprocessgroup` reports missing task profiles (for example `SystemServicePerformance`). Composer (PID 134) and
  gralloc (PID 133) still start and keep running, so this doesn't block M7. Effect: no per-service process groups or
  scheduling profiles for UI threads. The impact on frame pacing during the M7.5 soak is **unverified**. Don't re-enable
  cgroup v1 as a shortcut.
- **TEEGRIS (ADR-0004).** Normal UI doesn't use it: Mali secure rendering is already off in the baseline config, and the DPU
  calls the secure monitor only for protected (DRM) layers. Protected video and DRM layers stay unsupported.
