# 2026-11-07 M3.2 Readout at any time

## Build (host)
- Kernel a50-diag "A50 diag v7" (reference/m25-diag/0007-a50-diag-v7-readout-any-time.patch):
  - a50_dss_prepare (core_initcall): vmalloc 1 MiB text buffer, map DSS header/log_kernel (a50_map: ioremap_wc with our DT's
    no-map region, cached linear map + dcache clean with the stock DT) and the PMU; register a kmsg dumper; schedule the delayed dump.
  - a50_dss_dump(why): one dump per boot (atomic guard); BEGIN banner now carries the reason "(panic)", "(dump_after=N)",
    "(late_initcall)"; appends at the 0xf9000200 pointer; PMU INFORM3 = 0x12345671; SWRESET (as Test 19).
  - Panic: kmsg dumper, reason KMSG_DUMP_PANIC (runs after the panic text is logged).
  - a50_diag.dump_after=N (module_param, default CONFIG_A50_DIAG_DUMP_AFTER): 0 = late_initcall_sync (old behaviour), N > 0 =
    delayed work after N s, < 0 = only on panic. S-Boot drops the boot.img cmdline (docs/01-device.md:41), so the default is the knob.
- Test init tools/m32/init: everything to /dev/kmsg ("a50-m32:" prefix), countdown T-40..T-1 with uptime, then `exit 1`
  -> "Attempted to kill init!" panic (no CONFIG_MAGIC_SYSRQ in this config; the M2.2 init's sysrq-c could never have worked).
- tools/m22_build.sh: new switches A50_INIT=path and A50_DIAG_DUMP_AFTER=N.
- Images (our DT is flashed with them, as M3.1): src/m32/boot-m32-delay25.img 512a8ce3... (dump_after=25);
  src/m32/boot-m32-panic.img dc76718b... (dump_after=-1). Object check: kmsg_dump_register, queue_delayed_work_on present.
- Tools: tools/m32_read_618.sh IP OUT (newest BEGIN/END block, redaction; tested on the M3.1 dump: 11,710 bytes);
  tools/m32_run_test.sh IMG OUT (whole button-free cycle incl. rollback and pre-flight; stops with recovery text if 6.18
  does not return to Download mode). CAVEAT: if a test does not dump, the reader returns an OLDER dump -> always check the
  banner's reason tag.

## Tests

- Test B: boot-m32-panic.img. Expect banner "(panic)" and "Kernel panic - not syncing: Attempted to kill init!".
