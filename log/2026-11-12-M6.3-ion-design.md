## ABI and implementation plan

Source paths below refer to `src/samsung-a50-4.14-aa17rf2` for the donor and
`src/ack-6.18/common` for the target. Record this design before kernel changes.

- The donor `drivers/staging/android/uapi/ion.h` defines the fixed 24-byte
  allocation and query structures and 52-byte heap descriptions. Preserve
  those layouts and ioctl numbers `0xc0184900` and `0xc0184908` for native
  and compat userspace. Reserved query words must be zero. Implement the
  normal two-stage heap query and bounded partial results.
- Add a staging `ION_EXYNOS_COMPAT` frontend on `/dev/ion`. Use native
  `dma_heap_find` and `dma_heap_buffer_alloc`. ACK already provides `system`
  and `system-uncached` in `drivers/dma-buf/heaps/system_heap.c`, including
  cache maintenance, attachments and mmap behavior. Map the measured flag
  1 to cached and flag 64 to uncached. MAY_HWRENDER is a donor importer hint;
  native importers retain their DMA API cache handling.
- Advertise only the implemented system heap, with its measured name, ID
  and type. Native heaps free immediately, so its query flags are zero.
  Record this supported subset explicitly. The six reserved/secure heaps
  require their own backing and protection semantics. Reject unsupported
  allocation masks and protection/nozero/force-sync flags before allocation.
- Keep length rounding overflow-safe and reject zero length. Acquire a
  dma-buf and unused fd, copy the result out, then install the fd. Release
  both resources on copyout failure. No allocator lifetime is tied to the
  `/dev/ion` file descriptor.
- Samsung TRACK/UNTRACK (`0x6208/0x6209`) are process accounting operations,
  not allocation reference ownership. Reuse ACK's automatic task dma-buf
  records for lifetime and add a separate legacy counter to each record.
  TRACK increments, UNTRACK decrements and rejects an unmatched request.
  Native record cleanup handles last fd/mapping close, fork and exec.
  These hints do not change native fd or mapping reference counts.
  Reject the hints if native accounting is explicitly disabled.
- Enable native heaps and this frontend in one kernel test, retaining the
  M6.2 diagnostic masks, working USB and userdata guard. Repeat the captured
  lengths/masks/flags and test query validation, cached/uncached mappings,
  zero initialization, DMA_BUF_SYNC, tracking balance and copyout cleanup.
  Follow with a separate `COMPAT=y` candidate and an AArch32 replay helper.

## SysMMU work still required

The DT compatible match alone does not establish register-version, clock,
power-domain or IOVA compatibility. Compare the ten stock controller nodes
and the donor driver with ACK before enabling them. Validate DT bindings and
the actual probe path separately. CPU allocation/mmap tests cannot establish
device DMA correctness. M7 consumers will exercise hardware DMA.

The heap subset and SysMMU preparation remain explicit M6.3 acceptance items.
