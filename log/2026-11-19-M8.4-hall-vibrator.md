## Stock facts
- `hall` (`reference/stock-dt/dtbo.3.dts` ~2512): `hall,gpio_flip_cover` = gpa0-3 (fixup), pin `hall-irq` EINT, no pull.
  4.14 `drivers/input/misc/hall.c`: double read 50 ms apart, GPIO high = "open", with `CONFIG_HALL_EVENT_REVERSE=y`
  (baseline config) it reports `!level`, i.e. 1 = closed; code `SW_FLIP` (0x15).
- `certify_hall` (~2520): gpa0-2, pin `certify-hall-irq` EINT, no pull. `certify_hall.c` reports `!level`
  (1 = "attach"), code `SW_CERTIFYHALL` (0x1b). Both codes exist only in Samsung's input-event-codes.h (`SW_MAX` 0x20);
  mainline `SW_MAX` is 0x11.
- `sec_vib` (~2622): `sec_vib,ldo_type = 1`, `sec_vib,ldo_en` = gpa2-1 (fixup), `max_timeout` 10000 ms. 4.14
  `drivers/motor/sec_vib.c` switches that GPIO and registers a `timed_output` device "vibrator"; on stock,
  `/sys/class/timed_output/vibrator/enable` exists and `/sys/class/leds/vibrator` does not.
- Consumers (read-only on stock): the vendor HAL `vendor.samsung.hardware.vibrator@2.2-service` (`sec-vibrator-2-2`,
  user system) uses `/sys/class/leds/vibrator/{activate,duration,cp_trigger_index,cp_trigger_queue}`; Ubuntu Touch's
  `/usr/libexec/hfd-service` supports the Android vibrator HALs, `/sys/class/timed_output/vibrator` and
  `/sys/class/leds/vibrator/{activate,duration,state,trigger}`.

## Design (mainline only)
- Hall: a separate `gpio-keys` input "Hall sensors": flip cover `SW_LID` (gpa0-3), certified cover `SW_MACHINE_COVER`
  (gpa0-2), active low, `debounce-interval = 50`, stock pin group. logind's default `HandleLidSwitch` is suspend;
  `sleep.target` stays masked until M12, so a closed cover can only cause a failed suspend attempt (to be recorded).
- Vibrator: `gpio-leds` LED `vibrator` on gpa2-1 (active high) with `linux,default-trigger = "transient"`, giving
  `/sys/class/leds/vibrator/{activate,duration,state,trigger}`; the trigger switches the motor off after the requested
  duration. Samsung's extra `cp_trigger_*` attributes are not provided.
