Phone at 192.168.0.171 (home), baseline, pre-flight ALL CHECKS PASSED.
Open observation from M3.4: "Initramfs unpacking failed: invalid magic at start of compressed archive".
- Test images pack a 119-byte cpio.gz marker as the boot.img ramdisk (tools/m22_pack.sh); the real init is built into the kernel (A50_INIT). The kernel's built-in initramfs and any bootloader ramdisk both unpack at "Unpacking initramfs...".

- Baseline data partition: /dev/sda32 mounted on /userdata, ext4 with data=journal; /userdata/ubuntu.img 6442450944 B.
Open: whether 6.18 receives a real 10.8 MB ramdisk intact, and how often.

## Ramdisk logging test result (2026-11-10 00:16-00:19)
boot-m37-log.img cf04a2f9 + dt-clean.img. Runner exit 0, pre-flight ALL CHECKS PASSED. Dump: reference/m37-initramfs/2026-11-10-log-test1-dump.txt.
- first32 of the region (0x89000000) = all zeros. Past the real end: 0 nonzero bytes.
- The unpack loop skipped zeros up to +2097152 (exactly 2 MiB), where it found "63 64 65 76 33 00 ff ff ff ff ff ff 7f 00 00 00" ("cdev3"): not gzip, hence "invalid magic".
- So the bytes at the initrd address are NOT the ramdisk when populate_rootfs runs. Both earlier theories (trailing RAM junk; partial damage) are out. The leftover-RAM idea for the 119-byte marker intermittency is withdrawn.
- Those bytes are not in the 6.18 Image, the ramdisk, dt-clean.img or the baseline boot.img. Source UNVERIFIED. Kernel Image is ~8 MB, loaded near 0x80140000 (variable), so it does not reach 0x89000000.
- Open: is the ramdisk absent when the kernel starts (S-Boot) or overwritten during early boot?
